# v0.14.48 — 고친 것 셋(윈도우에서 자동 복원이 죽던 것 · 대기 알림의 표시 · 승인 없는 옛 예약 잡 둘의 주기 오류)과 안 고친 것

> 초안 · 2026-10-09 — 맥에서 잰 것만 「통과」로 적었습니다. 윈도우 실기 결과는 공개 전 관문에서 채웁니다(§4 미측정).

**한 줄씩**
- **고친 것 ①**: 한글·영문 윈도우(cp949·cp1252)에서 자동 복원이 로그 한 줄을 쓰다 죽던 것 — **모의 조건에서 더 이상 나지 않습니다.** 윈도우 실기 결과는 공개 전 관문에서 채웁니다.
- **고친 것 ②**: 기다리면 풀리는 큐 대기 3종이 빨간 「큐 막힘」으로 뜨던 **표시**를 바꿨습니다. **이것은 큐 막힘의 수리가 아니라 표시 변경입니다.**
- **고친 것 ③**: 승인 없는 옛 시드 예약 잡 둘이 주기마다 오류를 내던 것 — **맥 시험 자리 조건에서 더 이상 나지 않고** 「건너뜀」과 사유 표시로 보입니다. **그 두 잡을 살린 것이 아닙니다(실행되지 않습니다).** 윈도우는 재지 않았습니다.
- **안 고친 것**: 데몬의 막힘 분류표 자체의 오분류(§2-1) · 윈도우 설치 파일의 미서명과 스마트 앱 컨트롤 4551(§2-3) · 그 밖 §2.

## 1. 고친 것

### 1-1. 윈도우에서 자동 복원(phoenix)이 로그 한 줄을 쓰다 죽던 것
- **무엇이었나**: 기본 코드페이지가 UTF-8 이 아닌 윈도우(한글 cp949 · 영문 cp1252)에서, 데몬이 띄우는 자동 복원 스크립트가 로그 한 줄을 쓰다가 인코딩 예외로 종료코드 1 로 끝났습니다. 저널이 없어도 났습니다.
- **어느 판에 있었나**: 공개된 **v0.14.44 · v0.14.45 · v0.14.46 · v0.14.47 네 판 모두**에 있었습니다(해당 파일 바이트 동일). v0.14.47 이 만든 것이 아닙니다.
- **왜 CI 는 통과했나**: CI 는 `PYTHONUTF8=1` 을 두르고 돌았고 데몬은 그 보호 없이 스크립트를 띄웁니다 — CI 통과와 실기 실패는 모순이 아니었습니다.
- **무엇을 바꿨나**: 스크립트가 여는 텍스트 파일의 인코딩을 UTF-8 로 명시 · 표준출력/표준오류가 못 쓰는 글자를 만나도 죽지 않게 · 외부 도구(`schtasks` 등)의 출력을 바이트로 받아 명시적으로 풂 · 상태 저장 스크립트의 manifest 읽기/쓰기 UTF-8.
- **문면(판정문 그대로)**: 「cp949·cp1252 모의 조건에서 자동 복원이 죽던 것이 이 조건에서 더 이상 나지 않는다 · 윈도우 실기 미측정」.
- **이미 `.corrupt-<시각>` 으로 치워진 파일은 자동 복구하지 않습니다.** 앞선 판이 인코딩 오판으로 멀쩡한 로스터·저널을 `.corrupt-…` 로 치웠을 수 있습니다. 이 판은 그런 파일 가운데 UTF-8 로 읽으면 멀쩡한 JSON 인 것을 **로그로 알리기만** 합니다(되돌리지 않습니다 — 지금 상태보다 낡았을 수 있어 사람이 보고 정합니다). 알림은 세 종류(desired_roster · dept_roster · journal-*)에 한하고, 후보 중 최대 30개를 열며(열기 전 크기 1 MiB 초과는 건너뜀), 로그에는 그중 3개를 예시로 적고 나머지는 개수만 적습니다.
- **좌석이 실제로 되살아나는지는 별도입니다.** 이 판이 확인한 것은 「자동 복원이 그 줄에서 죽지 않는다」까지입니다.

### 1-2. 큐 대기 알림의 표시 — 기다리면 풀리는 것과 사람 손이 필요한 것을 나눔
- **무엇이었나**: 큐 머리가 600초 넘게 기다리면 사유와 무관하게 빨간 「⏳ 큐 막힘」이 떴습니다. 데몬은 사유를 가르는 값(처방 코드 14종)을 이미 보내고 있었지만 **표시가 그 값을 쓰지 않았습니다.**
- **무엇을 바꿨나**(앱 화면만 · 데몬·팩 무변경):

  | 부류 | 전(0.14.47) | 후(0.14.48) |
  |---|---|---|
  | 기다리면 풀리는 3종 | 빨간 「⏳ 큐 막힘 — …」 · 발화마다 팝업 | 「⏳ 배달 대기 중 — …」 · 「⏳ 승인 대기 중 — …」 · 「⏳ 일시 정지 중 — …」 · **회색** · **대기 구간당 팝업 1회**(그 뒤는 알람 이력만 갱신) · OS 배너 없음 |
  | 사람 손이 필요한 11종 | 빨간 「⏳ 큐 막힘 — …」 · 발화마다 팝업 · OS 배너 | **그대로** |
  | 모르는 코드 | 빨강 | 그대로 빨강 |

- **대기 구간**: 같은 좌석·같은 종류·같은 맨 앞 항목이 이어지는 동안입니다. 맨 앞 항목이 바뀌거나, 만료·되살림되거나, 배달되거나, 좌석이 끝나면 새 구간입니다. 구간을 끝낸 신호를 앱이 놓쳐도 **마지막 팝업 뒤 1시간이면 다시 띄웁니다**(시계가 뒤로 가도 실제 1시간).
- **두 가지를 나눠 알립니다**:
  - ⒜ 표시가 분류 신호를 쓰지 않았다 — **이번에 고쳤습니다.**
  - ⒝ 분류표 자체의 오분류 — **안 고쳤습니다.** 작업 중인 좌석이 대체 화면(`alt_screen` · 사람 손 부류)으로 분류되는 경우가 있습니다(codex 좌석 · 2026-10-09 15:03 · 15:18 · 15:34 실측 3회 · 작업이 끝나자 손대지 않아도 배달됨). 그런 좌석은 이 판에서도 **빨갛게 뜹니다.**
- **구판 데몬과 섞어 쓸 때**: 맨 앞 항목 id 를 보내지 않는 데몬과의 조합에서는 구간 구분이 제목 비교로 떨어집니다. 구판 앱은 이 개선을 받지 못합니다.
- **상주 표시는 없습니다.** 첫 팝업이 사라진 뒤 대기가 이어지는지는 알람 이력 탭에서 봅니다.
- CSO·master 좌석으로 가는 경보는 바뀌지 않았습니다.

### 1-3. 예약 잡의 `text_command` 승인 검사 ↔ 승인 없는 옛 시드 잡 둘
- **무엇이었나**: `text_command` 잡은 데몬이 셸로 돌리는 글이라, 데몬에 내장된 문구가 아니면 서명 승인이 있어야 돕니다. 예전 판이 넣어 둔 두 잡(`fleet-adoption-cost-digest` · `content-channel-health-watch`)은 승인이 없어 **주기마다 실행이 거부되고 오류(`schedule.error`)가 쌓였습니다.**
- **무엇을 바꿨나**(데몬의 예약 실행 판정과 `cys schedule list` 표시 · 승인 검사 코드·팩·앱 화면 무변경):
  - 그 두 잡의 **원래 문구**에 한해, 승인 저장소를 읽었고 그 문구의 승인이 **없다는 것이 확인되면** 오류로 세지 않고 `result=skipped` 로 건너뜁니다.
  - `cys schedule list` 의 잡 줄 끝에 `note=<종류>` 를 붙입니다(있을 때만) — `note=retired-seed-text` 는 그 문구라는 표시이고, `note=builtin-text-mismatch` 는 내장 잡의 문구가 내장 문구와 달라졌다는 표시입니다(데몬은 고쳐 쓰지 않습니다). 두 표시는 문구만 보고 붙이며 승인 여부를 말하지 않습니다.
- **문면(판정문 그대로)**: 「승인 없는 두 시드 잡이 주기마다 schedule.error 를 내던 것이, 맥 시험 자리 조건에서 더 이상 나지 않고 skipped + note 로 보인다 · 승인 저장소를 읽지 못하거나 승인 흔적이 있는 설치에서는 종전 오류가 남는다 · 윈도우 실기·부서 데몬 미측정」.
- **두 잡을 살리지 않았습니다.** 이 판에서도 그 두 잡은 **실행되지 않습니다** — 오류 대신 건너뜀으로 보일 뿐입니다. 시드 파일은 그대로입니다. 필요 없는 잡은 `cys schedule remove <id>` 로 지우세요.
- **종전 오류가 그대로 남는 경우**: 승인 저장소를 읽지 못한 설치 · 승인 흔적이 있는 설치(만료·무효·폴더나 환경이 다른 승인 포함). 고장을 건너뜀으로 숨기지 않습니다.
- **승인 검사는 느슨해지지 않았습니다.** 검증 세 회차 모두에서 승인 없이 실행되는 입력 · 승인 검사가 느슨해지는 입력 · push 증가는 나오지 않았습니다.
- **고지**:
  - ⒜ 처음에 함께 조사한 「결함 2(판 사이 문구 변경)」는 **전제에 근거가 없었습니다.** 이번에는 「같은 판 번호에 문구가 다른 내장 잡 = 경보(표시)만」으로 다뤘습니다.
  - ⒝ 구현의 세 번째 리뷰어 검증(r3)은 **없습니다** — 리뷰어 답이 모델 제공사의 안전 필터에 두 번 막혀 보고서가 나오지 않았고, **대체 절차**(부서장의 차분 직접 판독 + 그 커밋을 만들지 않은 좌석의 감사)로 갈음했습니다.
  - ⒞ **윈도우는 재지 않았습니다**(실기 · 부서 데몬 포함). 윈도우 러너의 같은 Rust 시험은 공개 전 관문에서 봅니다.

## 2. 안 고친 것
1. **막힘 분류표의 오분류**(§1-2 ⒝) — 데몬 쪽이며 이 판의 범위 밖입니다.
2. **큐 막힘 자체** — 큐가 언제 배달되고 언제 막히는가는 v0.14.47 과 같습니다.
3. **윈도우 설치 파일의 미서명 · 스마트 앱 컨트롤 4551** — 이번에도 그대로입니다. 설치 파일과 그 안의 실행 파일(cys-app · cysd · cys)은 서명돼 있지 않습니다(측정으로 확인). 4551 안내 경로는 종전 설계 그대로입니다. 코드 결함이 아니라 배포 속성(미서명)에 따른 알려진 제약으로 판정했고 — 단 스마트 앱 컨트롤의 차단 자체는 맥에서 잴 수 없어 **재지 못했습니다** — **서명 도입은 미정**입니다.
4. 이미 `.corrupt-…` 로 치워진 파일의 자동 복구(§1-1) — 알림만 합니다.
5. 데몬이 큐 경보에 싣는 hint 문구 — 그대로입니다.

- 자동 복원의 성패 판정(종료코드) · 좌석 생성·종료 — 무변경.

## 4. 미측정 — 숨기지 않고 적습니다
- **윈도우 실기** — 자동 복원(§1-1)이 실제 윈도우 설치본에서 죽지 않는지. 윈도우 러너의 시험 걸음(동봉 파이썬 · `PYTHONUTF8` 없이)은 써 두었고 **아직 돌지 않았습니다.** 그 걸음은 러너의 기본 인코딩이 cp1252 임을 스스로 단언하지 않습니다 — 로그의 `조건 native: stdout=…` 줄을 사람이 읽어 확인합니다.
- **한글 윈도우(cp949) 실기** — 맥의 모의 조건(로케일·끼움쇠)으로만 쟀습니다.
- **실제 앱 화면** — §1-2 는 맥에서 bun 시험과 코드 검수로 확인했습니다. 실제 화면 렌더 · 실제 타이머 · 윈도우 렌더 · 실제 OS 시계 조정/절전은 재지 않았습니다.
- 수정 뒤 좌석이 실제로 되살아나는지(§1-1).

- 예약 잡 건너뜀(§1-3)의 **윈도우 실기 · 부서 데몬**.
