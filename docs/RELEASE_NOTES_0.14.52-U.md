## 1. 알아 둘 한계 (사용자에게 보이는 것)
- **탭 점(F-01): 어떤 CLI 가 「일하는 중」을 보일 수 있나.** 역할 색 탭 점은 데몬이 그 좌석의 CLI 가 일하는 중임을 관찰할 때만
  깜박입니다. 지원: Claude Code 2.1.301 · Codex CLI 0.162.1(그 판에서 화면 문양을 채집). **Gemini / agy 좌석은 이 판에서 지원하지
  않는 계열이라 점이 깜박이지 않습니다**(늘 「알 수 없음」 표시). 그 CLI 를 따로 떼어 채집할 수 없었고, 살아 있는 gemini 좌석을 세
  시간 읽기 전용으로 기록했지만 리뷰 트래픽이 없었습니다. 다른 CLI 판에서는 「알 수 없음」이 더 자주 보일 수 있습니다. 쉬는 좌석을
  「일하는 중」으로 보이게 할 수는 없습니다 — 문법이 CLI 자신의 바쁨 제목을 열쇠로 삼기 때문입니다.
- **탭 점(F-01): 화면이 멈추면 「일하는 중」이 끝나지만, 시계가 돌면 끝나지 않습니다.** 정지 상한(같은 표본 N = 120 개)은 관찰하는
  화면 전체가 멈췄을 때만 걸립니다. 실제로는 멈췄는데 경과 시간 카운터(예: "1m 23s")가 계속 도는 CLI 는 자기 바쁨 제목이 바뀔 때까지
  「일하는 중」을 계속 갱신합니다 — 시계가 도는 멈춤은 상한이 잡지 못합니다. 부서장 판정 D2(N = 120)는 이 한계를 알고 그대로 섰습니다.
  반대쪽 한계: 기록이 짧은 큰 창에서 Codex CLI 0.162.1 은 「Working」 줄을 데몬이 읽는 화면 아래쪽 범위보다 위에 그리므로, Codex 의
  조용한 구간이 약 120 초를 넘으면 화면이 다시 바뀔 때까지 「알 수 없음」 표시가 됩니다(안전한 쪽 · 화면 표시만).
- **탭 점(F-01): 아직 확인하지 않은 상황.** 이 판에서 채집·측정하지 않은 것: 하위 에이전트나 백그라운드 작업을 기다리는 master,
  예약된 깨움 사이의 쉼과 그 뒤 실제 깨움, 비동기 출력이 들어오는 동안의 사람 초안, 실제 좌석 위 역할 × CLI 칸(시험 픽스처만 돌림),
  데몬·앱·화면을 거치는 시작·멈춤·만료 시간(모의 시계 UI 시험만 돌림). 이런 때 점은 「알 수 없음」일 수 있습니다. **master 와 CSO
  역할의 F-01 범위는 주장하지 않습니다.** 이 항목들은 다음 판 백로그로 넘깁니다(§3).
- **스크롤(B-230):** 작업공간 전환·입양 등 다시 그리기 뒤 첫 대화로 자동으로 뛰어오르던 결함을 맥(WKWebView)에서 고쳤습니다.
- **윈도우:** F-01 의 CI 칸은 더했지만 **한 번도 돌지 않았습니다**. 윈도우 터미널이 CLI 창 제목을 통과시키는지 재지 않았으므로 윈도우에서는
  점이 「알 수 없음」에 머물 수 있습니다. B-230 의 윈도우(WebView2) 확인 · B-229 의 윈도우 실기 렌더링도 하지 않았습니다(윈도우 기계
  없음). 맥에서 윈도우 대상 형식 검사(`cargo check --target x86_64-pc-windows-msvc --bin cysd --tests`) 한 번은 통과했지만, C 코드는
  대역으로 건너뛰었고 링크·실행은 하지 않았으므로 윈도우 동작에 대해서는 아무것도 말하지 않습니다.

## 2. 성능 영향 (U4-3) — 잰 것과 결정
측정: 3 회(measure-1/-2/-3), 매회 4 라운드 × 관찰자 끔(OFF)·켬(ON)·잠듦(SLEEP) × 250 초, 같은 작업량·같은 순서, 실제 PTY 좌석 64 개가 채집한 CLI 출력을 재생(사람 큐 짝을 받는 대기 좌석 4 개 별도).
OFF 는 관찰자가 아예 돌지 않는 대조군입니다.

- **(a) PTY 읽기 구간(파서 잠금을 쥔 구간)의 벽시계 시간 — 상한 한 번 초과, 부서장 결정으로 수용.** 상한은 「ON 이 OFF 보다 최대
  5 ms 이상 늘지 않는다」입니다. measure-1 은 +4.909 ms 로 상한의 98 % 에서 통과, **measure-2 는 +11.933 ms 로 초과**(ON 의 최대
  구간 13.12 ms · 540,396 개 구간 중 5 ms 를 넘은 것 2 개), measure-3 은 통과(ON 최대 2.30 ms 가 OFF 최대 4.57 ms 보다 작음).
  5 ms 를 넘은 구간은 세 번 모두 ON 에만 있었고(ON 3 · OFF 0 · SLEEP 0), 4 ms 초과는 ON 4 · OFF 1 · SLEEP 0, 1 ms 초과는 ON 8 ·
  OFF 3 · SLEEP 3 입니다. **원인은 가리지 못했습니다**: 원인을 가리려고 미리 잠가 둔 규칙으로 measure-3 를 돌렸지만 ON 의 긴 구간이
  다시 나오지 않았습니다(잠근 결과 「재현 안 됨」). 부서장이 이를 원래 상한의 통과가 아니라 **공개된 위험 결정**으로 받아들였습니다.
  - 근거의 정확한 범위: measure-3 에서 1 ms 를 넘은 네 구간(OFF 1 · ON 2 · SLEEP 1, 한 번의 측정)은 모두 벽시계 시간의 98.5 % 이상을
    읽기 스레드가 CPU 밖에서 보냈습니다 — 스케줄러가 내려놓았거나 구간 안에서 막혔다는 것과 맞지만, 어느 쪽인지는 이 계기로 가를 수
    없습니다. **관찰자와 엮인 내려놓임은 배제되지 않았습니다.** 그보다 앞선 ON 의 긴 구간(5.72 · 13.12 · 6.91 · 4.17 ms)은 CPU 계기가
    없던 측정이라 무엇이었는지 말할 수 없습니다.
  - 읽기 스레드 CPU 시간(최대 158 µs)은 **읽기 스레드 자신이 구간 안에서 하는 일이 적다는 것만** 보입니다. 이 시계는 읽기 스레드가 파서
    잠금을 잡은 뒤에 시작하므로, 관찰자가 잠금을 쥔 동안의 복사 작업이나 읽기 스레드의 잠금 대기를 재지 않습니다. 관찰자의 잠금
    점유 시간은 따로 쟀습니다: 최대 2,038.7 µs(measure-1, 완화 전) · 629.8 µs(measure-2) · 354.1 µs(measure-3), p99 는 7.75~18.2 µs
    (상한 p99 250 µs · 최대 1,000 µs). 최대값은 측정마다 약 6만 8천 개 표본 가운데 극단값 하나입니다.
- **(b) 사람 글이 제출될 때까지의 지연(ready_to_submission) — 측정 불가(UNMEASURED)로 출하.** 대조군(OFF) 자신의 p99 가 측정마다
  4,533.873 → 4,517.142 → 4,561.319 ms 로 흔들려(44.18 ms) 5 ms 차이를 가를 안정 한도를 넘었습니다. 충족도 통과도 아닙니다. 한 데몬
  안에서 끔·켬을 번갈아 재는 짝 측정 설계가 다음 판의 길입니다. 고해상도 대리 지표는 깨끗했습니다(measure-3: 배달 기한→시작 ON p99
  −0.011 ms · 최대 −0.118 ms, 붙임 스냅샷 ON 최대 +1.139 ms, 사람 큐 짝 136/136 세 측정 모두).
- **큐 동작은 그대로였습니다**: 세 측정의 모든 팔에서 사람 큐 짝 136/136 배달 · 지각·미배달 0 · 관찰자로 인한 추가 PTY 트래픽 0.
