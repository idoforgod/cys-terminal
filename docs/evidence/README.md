# `docs/evidence/` — 실측 아티팩트 보존 계약 (U-26 ② · 2026-08-24)

이 디렉터리는 **사람이 손으로 쓴 주장**이 아니라 **기계가 관측한 것**만 담는다.
부트 결정론 캠페인이 확정한 4대 근본원인 중 하나가 "**실측 없이 값을 골랐다**" 였고,
그 결과가 반복된 Windows 전용 사고와 '초록인데 깨진' 게이트다. 여기 있는 파일은
그 재발을 막는 유일한 물증이며, **지워지지 않는 것**이 이 계약의 핵심이다.

기계 집행자: `scripts/verify_evidence.py` · 검체 `H-EVID-1`(`run_bootstrap_health.py`).
계약을 어기면 **검체가 적색**이 된다. 문서만 있고 집행자가 없으면 그것은 계약이 아니다.

---

## 1. 무엇을 넣는가

| 넣는다 | 넣지 않는다 |
|---|---|
| 실기에서 캡처한 화면·키 반응·종료코드 | 사람의 요약·해석만 있는 글 |
| 벤치마크 원측정치(반복 횟수·분산 포함) | "대략 2초" 같은 추정치 |
| 재현 명령이 딸린 프로브 산출물 | 재현할 수 없는 1회성 관측 |
| 계측기 자기검증(수리 전 적색) 출력 | 모델링·추론으로 만든 값 |

**원칙**: 이 디렉터리의 값을 근거로 코드의 상수를 고를 수 있어야 한다.
그럴 수 없는 값이면 여기 있을 자격이 없다.

## 2. 파일 이름

```
<kind>-<YYYY-MM-DD>-<slug>.json
```
`kind` ∈ `probe`(관측) · `capture`(화면 캡처) · `bench`(측정치) · `run`(실행 기록).
`slug` 은 `[a-z0-9-]+`. 날짜는 **측정한 날**이지 커밋한 날이 아니다.

## 3. 파일 안에 반드시 있어야 하는 것

| 키 | 뜻 | 왜 필수인가 |
|---|---|---|
| `schema` | `"cys-evidence/1"` | 스키마 없는 파일은 다음 사람이 못 읽는다 |
| `id` | 파일명(확장자 제외)과 **동일** | 이름과 내용이 갈리면 인용이 깨진다 |
| `title` | 한 줄 설명 | — |
| `measured_on` | `YYYY-MM-DD` (파일명 날짜와 동일) | 값의 유통기한 |
| `tool` | 무엇으로 쟀는가 | 계측기를 모르면 값을 못 믿는다 |
| `platform` | OS·대상 버전·격리 조건 | mac 초록·Windows 적색이 이 제품의 사고 형태다 |
| `repro` | **그대로 붙여넣어 다시 잴 수 있는 명령** | 재현 불가는 증거가 아니라 전언(傳言)이다 |
| `provenance` | 누가·어떤 레인에서 관측했고, 이 파일은 원측정인가 전사(轉寫)인가 | 전사를 원측정으로 파는 것이 최악의 오염이다 |
| `observations` | 관측 목록(빈 배열 금지) | 결론이 아니라 관측을 남긴다 |

`observations[]` 의 각 항목은 `fact`(관측된 사실) 과 `evidence`(그 근거가 되는 원문·출력)
를 가진다. `derived` 가 참인 항목은 **관측이 아니라 추론**이며, 그때는 `derived_from` 에
어느 관측에서 나왔는지 적는다.

## 4. 넣으면 안 되는 것 (기계가 막는다)

- **자격증명·토큰**: `sk-ant-…` · `ghp_…` · `AKIA…` · `-----BEGIN … PRIVATE KEY-----`
- **사용자 홈 절대경로**: `/Users/<이름>/…` · `C:\Users\<이름>\…`
  (재현 명령에는 `$HOME`·`%USERPROFILE%`·`<cwd>` 자리표시자를 쓴다)
- **개인 이메일·계정 식별자**

## 5. 보존(retention) — **삭제가 조용히 일어나지 않는다**

아래 대장(§6)과 실제 파일은 **1:1** 이어야 한다. 파일을 지우면 대장에서도 지워야 하고,
그 삭제는 diff 에 반드시 드러난다. 대장에 없는 파일이 생겨도, 대장에 있는 파일이 사라져도
`H-EVID-1` 은 적색이다.

> 왜 이렇게까지 하는가 — 측정치가 불편할 때 **파일을 지워 초록을 만드는 것**이
> 이 캠페인이 명시적으로 차단하기로 한 reward-hack 이기 때문이다(`retention hard gate`).
> 증거는 반박의 대상이지 삭제의 대상이 아니다. 값이 틀렸다면 **새 측정으로 덮되 옛 파일은 남긴다**
> (`superseded_by` 키를 옛 파일에 추가한다).

## 7. 커밋 규율

1. **값을 쓰는 커밋과 증거 커밋은 같은 커밋**이다. 상수를 고쳐 놓고 증거를 나중에 붙이면
   그 사이의 리뷰는 근거 없는 리뷰다.
2. 증거 파일은 `git add <경로>` 로 **명시 스테이징**한다(`git add -A` 금지 — 릴리스 레인 규약).
3. 커밋 메시지에 `Evidence: docs/evidence/<파일>` 한 줄을 남긴다.
4. 전사(轉寫)본은 `provenance` 에 원 관측의 출처와 "이 레인이 재측정하지 않았다"를 **명시**한다.
