## 1. 들어간 것

### 1-1. F7 — 승인 저장소(approvals.json · approvals-ttl.json)를 읽는 해독기가 하나로
- **무엇이었나**: 승인 저장소를 읽는 곳이 둘이었습니다 — 데몬의 승인 로더와, 「승인 없는 옛 시드 예약 잡을 건너뛸지」 정하는 원문 점검(`schedule.rs`). 점검은 자기 JSON 해독을 따로 갖고 있었고, 맨 배열 안에서 **알려진 필드가 두 번 나오면** 로더는 오류로 보는데 점검은 첫 값을 취해 「흔적 없음」으로 보았습니다.
- **재어 본 것**: 고치기 전 태그의 두 해독기에 21개 행(바이트 열)을 같이 넣는 일치 시험이 **3건 실패 · 1건 통과**였고, 어긋난 행은 정확히 하나(`bare-dup-known-field` — 로더는 오류, 점검은 오류 아님)였습니다.
- **바꾼 것**(데몬 파일 둘): `approval.rs` 에 `decode_records_text` 하나를 두고 로더와 점검이 모두 그것을 부릅니다. 로더의 오류 문구는 바이트 단위로 전과 같습니다.
- **그대로인 것**: 로더가 21개 행에 내리는 판정은 고치기 전·후 모두 같게 고정했습니다(고정 시험 녹색). 승인 결정은 바뀐 로더 경로를 타지 않습니다.
- **눈에 보이는 변화**: 로더가 이미 거부하는 **망가진 저장소**는 이제 옛 시드 건너뜀 점검에서도 오류로 취급됩니다. 저장소가 없거나 비어 있는 보통 설치는 전과 같이 건너뜁니다(시험으로 확인).
- **시험**(맥 · 빈 임시 홈): 데몬 시험 2251 → 2255 통과, 실패 0. 변이 시험 둘(첫 값 취하기 복원 · 해독 오류를 빈 값으로 삼키기)은 모두 시험이 잡았습니다.

### 1-2. F10 — 고친 훅은 드리프트로 보이고, `cys doctor --lanes` 가 생겼습니다
- **무엇이었나**: `hooks/` 아래 vendor 파일을 고치면 그 수정은 업데이트가 덮어쓰지 않고 제자리에 남습니다(전부터). 그런데 **무엇을 고쳤는지 한눈에 보이지 않았고**, 영속하는 방법도 훅 안내문에 없었습니다.
- **바꾼 것**(A·B 두 쪽):
  - `cys doctor` 의 `pack-drift` 항목이 `hooks/` 파일을 일곱 상태로 가릅니다: `same` · `drift` · `behind` · `drift+behind` · `missing` · `unreadable` · `extra`. 이 가운데 `drift` · `drift+behind` · `missing` · `unreadable` 은 WARN 으로 세고 파일 이름과 해시 셋(디스크 · 설치 매니페스트 · vendor)을 보입니다. `behind` · `extra` 는 나열만 합니다. 등급은 OK / WARN / SKIP 뿐이고 **FAIL 은 내지 않습니다**(doctor 종료코드는 FAIL 개수 그대로).
  - 순회가 깊이 8 · 항목 4096 상한이나 열 수 없는 폴더에 막혀 끝까지 못 갔으면 「순회 불완전」을 밝히고 WARN 으로 셉니다(깨끗하다는 뜻이 아닙니다).
  - 새 명령 `cys doctor --lanes [--json]` — 본부 팩(`~/.cys/pack`)과 모든 부서 팩(`~/.cys/pack-dept-*`)을 팩 폴더당 한 줄로 보입니다. **읽기 전용** · 아무것도 쓰지 않고 데몬에 접속하지 않으며 종료코드 0 입니다(소스 고정 시험 + 실제 바이너리 실행으로 트리 해시가 전·후 같음을 확인).
  - 안내 문장 하나(`cys` 의 상수 `HOOKS_LOCAL_GUIDANCE` 가 유일한 원본): 「`hooks/` 아래 vendor 파일의 수정은 제자리에 보존됩니다. 영속하는 쪽은 `~/.cys/local/hooks/<이벤트>.d/` 에 자기 훅 파일을 두는 것입니다(업데이트·치유 불가침). 제품에 반영할 개선이면 `cys pack-merge --file <rel> --propose` 로 제안 패치를 만드세요.」 — `cys doctor` 의 드리프트 줄 아래, `cys pack-ownership <rel>`(vendor `hooks/` 파일) 출력, 그리고 `pack-guard.sh`(`hooks/` 아래 편집에 한해 안내 문장만 · 막지 않음)에 같은 말로 실립니다. `pack-guard.sh` 쪽은 세 문자열(`~/.cys/local/hooks/<이벤트>.d/` · `cys pack-merge --file` · `--propose`)이 들어 있는지를 시험(`test_pack_guard_hooks_guidance.py`)이 고정합니다.
  - `hooks/README.md` 에 §7(드리프트를 읽는 법)을 더했습니다.
- **알아 둘 것**: `behind`(내가 안 고쳤는데 vendor 만 전진)는 **지금 돌고 있는 `cys` 에 내장된 팩**을 기준으로 판정합니다 — 옛 `cys` 는 자기 내장본에 대해서만 말합니다. 그리고 이 판이 들어가기 전에 **훅을 직접 고쳐 둔 레인은 이 판을 받은 뒤 `pack-drift` 가 WARN 으로 뜹니다**(의도된 동작입니다).
- **만들지 않은 것**: 앱 화면의 업데이트 알림 개수(그 값의 원천 — 앱에서 닿는 설치 계획과 업데이트 전 vendor 파일 — 이 지금 제품에 없습니다 · 백로그 B-072) · 내보내기 명령(기존 `cys pack-merge --file <rel> --propose` 를 씁니다) · `cys pack-drift` 명령.
- **시험**(맥 · 빈 임시 홈): `--bin cys` 473 → 480, `--lib` 746 → 755 통과, 실패 0. 변이 시험 15개(F7 둘 포함) 모두 시험이 잡았습니다. 설계가 적은 시험 가운데 「그 팩으로 시험 데몬을 띄워도 동작이 같다」는 통합 반쪽은 쓰지 않았습니다(데몬은 훅 파일을 읽어 시작하지 않고 이번 변경은 데몬 시작에 닿지 않기 때문 — 보고서에 미적용으로 적음).

### 1-3. B-057 — soul 의 절대규칙 주입(L0)이 비어 있던 것
- **무엇이었나**: 세션 시작·재개 때 `inject-context.sh` 가 soul.md 에서 L0 를 뽑는 선택기(`## [` 로 시작하는 제목부터)가 오늘의 soul 파일 모양과 맞지 않아 **제목 하나도, 한 바이트도** 주입하지 못했습니다. 실제 레인 soul 파일 여섯 개(본부 · dept-1~5, 13,824~52,740 B)를 읽기 전용으로 대 보니 **옛 훅의 L0 는 여섯 모두 제목 0개 · 0 B** 였습니다(파일 해시는 전·후 같음).
- **바꾼 것**(훅 한 블록): 선택기를 없애고, soul 의 `## ` 제목을 **전부** 나열한 뒤 전문을 읽으라는 포인터 한 줄을 붙입니다. 실제 레인 여섯에서 새 훅은 제목 전부 + 포인터(1,180~2,202 B)를 냅니다.
  - **포인터 줄이 맨 앞**이고 경로는 **홑따옴표로 감싼** `cat '<경로>'` 입니다(공백·홑따옴표가 든 경로도 그대로 실행됨 — 시험이 bash 로 실제 실행). 제목이 아무리 길어도 포인터가 먼저 나옵니다(3,000자·5,000자 제목 시험).
  - 제목 목록이 8,192 B 를 넘으면 조용히 자르지 않고 생략 개수를 밝히는 한 줄을 냅니다. soul 전체가 32,768 B 를 넘으면 비대 경고 한 줄을 냅니다(두 한도는 기존 값).
  - **새 경고 두 줄**(제품 문구 — 오너 확인 대상): ① soul 파일을 못 읽을 때 `⚠ soul 파일을 읽지 못했다 — L0 주입 0B(정체·절대규칙 미주입). 이 상태로 작업하지 말고 파일과 권한을 확인하라: <경로>` ② 제목이 0개일 때 `⚠ soul 에서 '## ' 절 제목을 0개 찾았다 — 제목 목록이 비었다(L0 0B 경보). 위 명령으로 전문을 읽어라.`
  - CRLF 로 저장된 soul 도 제목 끝에 캐리지 리턴이 붙지 않게 처리합니다.
- **본부에서 쓰던 임시 수정과 다른 점**: 본부 레인이 로컬로 고쳐 둔 H1 형태와 **글자 단위로 같지 않습니다** — 이 판은 포인터를 맨 앞에 두고 경로를 따옴표로 감쌉니다. 본부가 같은 파일에 로컬로 넣어 둔 **H2(작업 컨텍스트 블록) · H3(.state_log 필드)는 이 판에 들어 있지 않아**, 다시 얹지 않으면 업데이트 뒤 사라집니다(H2 는 제품이 싣지 않는 모듈이 필요하고, H3 는 부트 경로에 새 호출을 더해 0.14.50 에 싣지 않기로 했습니다).
- **그대로인 것**: 시작·재개 외 입력(`clear` · `compact`)은 L0 블록이 없는 그대로 · 블록 밖 출력은 옛 훅과 **바이트 같음**(4 입력 × 소울 4종 × 역할 2종 = 32개 조합 중 32 일치 — 종료코드 · 표준오류까지) · soul 파일이 아예 없으면 여전히 조용히 건너뜁니다.
- **시험**: 새 파일 `test_inject_context_soul_l0.py` 17건 통과(옛 훅에서는 첫 판 12건 중 9건 실패 · 포인터 순서·인용 수리 전 시험은 10건 실패 1건 오류에서 시작) · 변이 6개(포인터 순서 · 따옴표 없음 · 따옴표 이스케이프 없음 포함) 모두 잡힘 · 건강성 러너 164 통과 / 0 실패 / 1 해당 없음. 건강성 시험 H-SOUL-LANE-1 은 L0 가 본문 대신 제목을 싣게 되어 표지 위치를 제목 줄로 옮겼습니다(레인 우선 판정 네 조건은 그대로, 포인터가 레인 soul 을 가리키는지 한 조건 추가).

### 1-4. F5 — 제품 자신의 CPU 를 보고합니다(보고 전용 · 관문 아님)
- **무엇이 생겼나**: `javis_resource_gate.py product-cpu [--json]` — 앱 · 화면(WebKit) 보조 프로세스 · 제품 데몬 · 제품 잡의 %CPU 를 한 번에 보입니다(에이전트 CLI 는 따로 한 줄). 자기 `ps` 읽기(최대 1.5초)를 하고 **항상 종료코드 0** 이며 실패는 `state` · `reason` 필드로 나옵니다. 텍스트 `check` 끝에 한 줄이 더 붙습니다(자식 프로세스 최대 3.0초, 판정 뒤에 읽는 순서). 윈도우에서는 「unavailable」이고 자식을 띄우지 않습니다.

- **재어 본 것**(맥 · 2026-10-10): 세 번 실행 모두 0.054~0.057초(자식 포함 전체 0.15초) · 텍스트 `check` 전체 0.41초에 한 줄이 붙음. 그 실행에서 본 값: 앱 1 · 앱 보조 3 · 데몬 7 · 잡 7 · 에이전트 CLI 45 · 남의 앱 보조 27(제외). 맥의 값은 `ps` 평균이라는 표시가 줄 끝에 붙습니다.

- **시험**: `test_resource_gate_product_cpu.py` 43건 통과 · 변이 9개 모두 잡힘.

## 5. 알려진 불안정한 윈도우 데몬 시험과 공개 전 관문 G6
- 윈도우 건강성 걸음의 데몬 전체 시험(`cargo test --bin cysd -- --test-threads=1`)에는 **간헐 실패 묶음**이 있습니다. 저장된 윈도우 26회 실행 가운데 17회에서 한 건 이상 실패했고(같은 코드가 완전히 통과한 회차도 있음), 20개 시험 이름 · 23개 식별(이름 + 메시지)이 나왔습니다. 7회에서는 한 시험이 단언에 실패하면서 공유 시험 잠금(`REAP_ENV_LOCK`)을 쥔 채 죽어 뒤따르는 시험 7~11개가 `PoisonError` 로 첫 줄에서 실패했습니다 — 그 시험들은 **자기 점검을 하나도 돌리지 못한 것**이라 초록으로 보이지 않고 가려진 것입니다. 0.14.49 는 「Rust 가 바뀌지 않았다」를 이 실패의 근거로 삼았으나, **그 근거는 이 판(F7 이 Rust 를 바꿈)부터 만료됩니다.**
- **관문 G6**(부서장 결정): 공개 전에 후보의 윈도우 데몬 시험 로그를 고정 목록(`PINNED-SET.json` — 시험 이름 · 메시지 · 패닉 위치)과 도구(`check_health_log.py --source-root`)로 대조합니다. 목록에 없는 실패 이름, 또는 목록에 있는 이름이 다른 위치 · 메시지로 실패하면 **중지**합니다. `PoisonError` 사슬이 나타나면 그 작업을 한 번만 다시 돌리고, 가려졌던 시험들이 실제로 실행된 런이 있어야 공개하며, 두 번째 사슬이면 중지하고 보고합니다.
- 한계: 목록은 26회에서 만들었으므로 26회에 한 번보다 드문 간헐 실패는 처음 나올 때 「새 실패」로 읽힙니다. 시험 잠금을 `into_inner` 로 고쳐 한 시험의 실패가 다른 열 개를 가리지 않게 하는 일은 대장 B-069 입니다(이 판 밖).
