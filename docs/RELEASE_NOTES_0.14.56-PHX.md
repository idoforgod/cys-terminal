# cys-terminal v0.14.56 — 릴리스 노트: PHX 레인 절 (사전 복원 스크립트 · 복원 계획 · 재확인) — 초안

> 초안 · 2026-10-29 — 이 파일은 0.14.56 릴리스 노트 가운데 **PHX 레인 몫**입니다. 0.14.56 에는 여러 레인이 들어가므로, 릴리스
> 노트를 엮는 사람이 이 절을 그대로 옮겨 붙이도록 따로 둡니다(문장은 줄여도 되지만 사실은 바꾸지 않습니다). 맥에서 잰 것만
> 적었습니다. 브랜치 `fix/0.14.56-phx-impl` (S1 `75dc8d28` … S6b `376d90c4`, 이 절은 S6c).

**한 줄씩**
- **들어간 것**: 데몬이 좌석을 자동 복원하기 **전에** 사용자가 고른 python 스크립트 하나를 돌릴 수 있습니다(allow 파일
  `~/.cys/local/phoenix-allow.sha256` 의 `default` 줄 · 해시가 맞는 그 바이트만 · 두 상한 · 끝난 뒤 복원 계획을 다시 물어
  복원할 것이 없다고 증명될 때만 내장 복원을 건너뜀). 설명은 `docs/INSTALL.md` 「사전 복원 스크립트」 절.
- **allow 파일이 없으면 아무것도 바뀌지 않습니다** — 오늘과 같은 내장 복원만 돕니다(맥 시험으로 고정: 기본 부팅은 훅 잠금
  탐지에도 표준입력 잠금에도 닿지 않습니다).
- 함께 들어간 것: phoenix 의 읽기 전용 `plan` 서브커맨드 · 내장 복원이 「다른 복원이 진행 중」으로 물러났을 때 30초 뒤 한 번
  다시 확인 · 그 결과를 복원 로그 끝줄과 알림에 이유와 함께 적음.
- **남는 위험(한 문장)**: macOS·Linux 에서 사전 복원 스크립트가 표준입력을 돌리지 않고 띄운 도우미 프로세스가 스크립트보다
  오래 살면 `hook.run.lock` 을 계속 쥐고 있어서, 그 도우미를 끝낼 때까지 다음 부팅은 자동 복원을 **전혀** 하지 않습니다(알림으로
  원인과 해결법을 알립니다 — 도우미는 `</dev/null` · `stdin=DEVNULL` 로 띄우십시오).
- **되돌리는 법**: allow 파일에서 그 줄을 지우거나 파일을 지웁니다.

**재지 못한 것 (UNMEASURED)**
- 윈도우 실기 전부: Smart App Control 이 켜진 PC 에서 동봉 python 이 사용자 `.py` 를 훅으로 돌릴 때의 동작 · 작업 스케줄러가
  띄운 데몬의 환경에서 훅이 받는 환경 · 훅의 Job 중첩과 「띄운 뒤 Job 에 넣기 전」 창 · 윈도우에서의 정지(90초) 판정 주기.
  이 판의 윈도우 검체(windows-health 차단 셀 `hook_job_win_tests::` · `phoenix_plan::` · `reclaim::tests::probe_`, windows-build
  T5 스모크 ⑩·⑩b)는 배선만 했고 아직 한 번도 돌지 않았습니다.
- 끝에서 끝 시험 `test_phoenix_e2e_hook.py` 는 실 cysd 가 필요해 릴리스 레인의 phoenix 글롭(macOS arm64)에서만 돕니다 —
  GitHub 러너에서의 첫 실행이 태그 실행입니다. 태그 전 점검에서 phoenix 글롭을 한 번 돌리기를 권합니다.

**코드 서명 · Smart App Control**: 이 레인은 배포되는 윈도우 실행 파일·DLL 을 더하거나 이름을 바꾸거나 교체하지 않고,
업데이터가 그것들을 교체하는 방식도 바꾸지 않습니다(훅은 이미 배포되는 동봉 python 으로 돕니다).
