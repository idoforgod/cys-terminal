# v0.14.47 — 계측·관측 보강: 큐가 막혔을 때 남는 진단(`screen_diag`)에 값 넷을 더했습니다

> 2026-10-08 · v0.14.47 — 수치는 실제로 잰 것만 적었고, 재지 못한 것(윈도우 실기 · 살아 있는 레인에서의 값 분포)은 §3 · §4 에 숨기지 않고 적었습니다.

**이 판은 큐 막힘의 판정을 바꾸지 않는다.** 큐가 언제 배달되고 언제 막히는가는 v0.14.46 과 같습니다. 달라지는 것은 막혔을 때 남는
진단 기록에 값이 넷 늘어난다는 것 하나입니다 — 다음 판에서 무엇을 고칠지 정하려면 먼저 재야 하는 값들입니다.
**윈도우에서의 효과는 검증되지 않았다**(§3).

## 1. 바뀐 것

- `queue.starved` 이벤트 payload 와 `queue-blocked.json` 행의 `screen_diag` 객체에 **추가형 키 넷**이 생겼습니다(기존 다섯 키는 이름·뜻 그대로 · payload 최상위 키 수는 16 그대로).
  - `after_cursor_dim` (`true`/`false`/`null`) — 커서 행에서 커서 열부터 줄 끝까지, 커서 열의 칸이 반전이면 그 한 칸을 빼고, 남은 글자 칸(공백류 제외)이
    하나 이상이고 **전부 흐림(SGR 2)** 이면 `true`, 흐림 아닌 것이 하나라도 있으면 `false`, 남은 글자 칸이 없거나 커서가 화면 밖이면 `null`.
  - `cursor_col` (수/`null`) — 커서 열(0 기반). 커서 행이 화면 밖이면 `null`.
  - `alt_screen` (`true`/`false`) — 그 좌석이 대체 화면인가.
  - `human_idle_secs` (수/`null`) — 마지막 사람 입력 뒤 지난 초. 기록이 없으면 `null`(0 으로 접지 않습니다).
- 그 값을 읽을 수 있도록 저장소 안의 화면 파서 사본(`vendor/vt100/`)이 **흐림(SGR 2)을 칸에 기억**합니다(SGR 22 · 0 으로 내림 · `Cell::dim()` 으로 읽기).
  원본 파서는 SGR 2 를 버렸습니다. 흐림은 **읽기 전용 재료**입니다 — 칸 비교와 다시 그리기 출력(`contents_formatted` · `contents_diff`)에는 넣지 않았습니다.
  패치 자리와 재적용 방법은 `vendor/vt100/CYS-PATCHES.md` 에 적었습니다.
- 사용 설명서의 `screen_diag` 설명에 키 넷을 더했습니다.

## 2. 그대로인 것

- **큐 배달의 판정** — 게이트의 관측 구조체와 판정 함수는 고치지 않았습니다. 새 값을 읽는 곳은 진단 하나뿐이고, 게이트 · 배달 · 컨텍스트 순환 · 직접 보내기 길은 이 값을 읽지 않습니다.
  입력줄에 회색 안내문이 떠 있는 대체 화면 좌석의 큐 막힘과, 순환의 회색 글 오판은 **이 판에서 고쳐지지 않습니다.**
- 경보 요약 줄(좌석에 타이핑되는 한 줄)과 처방 문장 — 무변경. 새 키는 요약 줄에 실리지 않습니다(시험이 지킵니다).
- 화면을 다시 그릴 때 내보내는 바이트 — 무변경(§4 의 재생 대조).
- CLI · GUI(`ui/`) · 팩 · 역할 지침 — 변경 없음. `ui/` 와 팩 스크립트에 `screen_diag` 를 읽는 자리는 없습니다(0건).

## 3. 알려진 한계 — 정직하게

- **윈도우에서의 효과는 검증되지 않았다.** 윈도우의 콘솔 계층(ConPTY)이 SGR 2 를 데몬까지 넘겨 주는지 재지 못했습니다. 안 넘겨 주면 `after_cursor_dim` 은
  회색 글 위에서도 `false` 로 남습니다(동작에는 영향이 없고 진단 값만 그렇습니다). 윈도우 컴파일 검사(타입체크)까지만 했습니다(§4).
  - **윈도우 실기 꼬리 걸음**: 윈도우 실기에서 진단 한 장(회색 글이 그려진 순간의 `queue-blocked.json` — `screen_diag` 의 아홉 키)을 받을 때, **SGR 2 가 넘어왔는지 함께 대조**합니다 — 회색 글이 떠 있는 화면과 `after_cursor_dim` 값을 1:1 로 맞대어 봅니다.
    `false` 만으로 SGR 2 가 넘어오지 않았다고 단정하지 않습니다(흐림이 아닌 글자가 하나만 섞여도 `false` 이고, 색으로 그린 회색 글이나 화면을 읽은 시점의 차이도 `false` 를 냅니다) —
    같은 관측 시점의 원시 바이트에 SGR 2 가 있는지 · 커서 범위(`cursor_row` · `cursor_col`) · 속성이 섞였는지를 대조해 원인을 확인합니다.
- **살아 있는 레인에서의 값 분포는 아직 없습니다.** 새 키가 실제 막힘 행에서 어떤 값으로 쌓이는지는 이 판이 깔린 뒤에 재는 것입니다.
- `after_cursor_dim` 과 기존 `ghost_after_cursor` · `draft_visible` 은 서로 다른 순간에 화면을 읽습니다 — 그 사이에 화면이 바뀌면 한 프레임의 값이 아닐 수 있습니다(기존 `cursor_row` 도 같습니다).
- `queue-blocked.json` 의 `screen_diag` 가 사유가 기록된 순간의 스냅샷이라는 점은 v0.14.45 와 같습니다.
- 입력줄의 회색 글이 흐림(SGR 2)으로 그려진다는 것은 시험 자리의 claude 2.1.294 에서 잰 사실입니다. 다른 판 · 다른 에이전트의 입력줄은 재지 않았습니다.
