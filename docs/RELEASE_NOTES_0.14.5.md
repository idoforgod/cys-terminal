# cys 0.14.5 — Windows 형제 import 실패 수리 (D1)

## 무엇이 고쳐졌나

**Windows 사용자에게 조용히 깨져 있던 기능이 복구됩니다.**

Windows 설치본의 동봉 파이썬은 embeddable 형태(`python312._pth`)라 표준 경로 계산을 우회합니다.
그래서 자비스 팩의 `bin/` 스크립트들이 **같은 폴더의 형제 모듈을 불러오지 못했습니다**:

```
File "C:\Users\...\.cys\pack\bin\javis_event.py", line 19, in <module>
    import javis_scrub
ModuleNotFoundError: No module named 'javis_scrub'
```

훅이 **실패해도 무조건 성공으로 끝나는(fail-open)** 구조라 이 고장은 **아무 증상도 내지 않았습니다.**
에러 창도, 로그도, 배지도 없이 해당 기능만 조용히 동작하지 않았습니다 — 그래서 아무도 신고하지
않았고, macOS 에서는 재현되지 않아 CI 도 통과했습니다.

0.14.5 는 팩 스크립트 7개에 경로 가드를 넣어 이를 수리하고, **같은 부류가 다시 들어오지 못하도록
게이트를 3중으로** 세웁니다.

## 영향 범위

- **Windows 사용자**: 메모리 증류·이벤트 처리·오케스트레이션·작업 관리 등 팩 기능이 정상 동작합니다.
- **macOS 사용자**: 기능 변화 없음(원래 정상 동작). 팩·게이트 개선분만 반영됩니다.
- 본체(Rust/GUI) 코드 변경 **0줄** — 이 릴리스는 팩과 검증 배선이 전부입니다.

## 이 릴리스에서 새로 생긴 안전장치

- **회귀 스위트** (`test_import_guard.py`) — 정적 판정(AST) + 실런타임 재현(자식 프로세스 격리)
  + 셀프테스트. **적대 검증 3라운드**를 거치며 BLOCK 9건을 수용해 다시 썼습니다.
  - 실런타임 판정이 종료코드가 아니라 **형제 모듈이 실제로 적재됐는지**를 봅니다 —
    팩 관례가 import 실패를 `try/except` 로 삼켜 종료코드 0 이 성공을 뜻하지 않기 때문입니다
    (실측: 검사 대상 8종 중 3종이 그렇습니다).
  - `sys.path` 값이 추적 불가능한 위치로 새면 **금지**합니다. 우회 표현을 하나씩 막는 대신
    기본 처분을 뒤집었습니다.
- **T6** (`windows-build.yml`) — 동봉 embeddable 파이썬으로 스위트를 실제로 돌립니다.
  기존 3레인은 전부 macOS/ubuntu 라 **문제의 런타임에서는 0회 실행**되고 있었습니다.
- **레인 대조 게이트 확장** — 부분 레인 계약(포함·필수 보유·무조건 실행)으로,
  검증 스텝을 조건부로 죽여도 게이트가 잡습니다.
- **배포 자동화 4종** — zip 변형·체크섬·홈페이지 배포·원격 검증 6항목.
  모두 기존 발행본을 **바이트 재현**하는지로 교정했습니다.
