# v0.14.30 — 받은 파일이 열리는지를 발행 전에 기계가 확인합니다

이번 판의 확정된 변경은 **릴리스 검증의 사각지대 하나를 닫은 것**입니다. 여러분이 브라우저로
받은 설치 이미지(.dmg)를 여는 순간 macOS가 보는 것은 **그 이미지 자신의 서명과 공증 티켓**인데,
지금까지 발행 게이트는 이미지 **안의 앱**만 검사했습니다. 봉투가 비어 있어도 통과할 수 있는
구조였습니다. 이제 발행 전에 그 봉투까지 기계가 확인합니다.

팩·데몬 버그 수정(아래 첫 절)은 같은 릴리스에 함께 실릴 예정이며, 통합 시점에 확정 문안으로
교체됩니다.

## 릴리스 게이트 강화 — DMG 자체 공증 티켓·Gatekeeper 평가(⑦)

발행 게이트(`scripts/release-gate-gatekeeper.sh`)에 **⑦ DMG 봉투 축**을 넣었습니다. 검사 대상은
브라우저 다운로드와 같은 격리 속성(`com.apple.quarantine`)을 붙인 **사본**이고, 이미지를 마운트
하기 **전에** 두 가지를 봅니다.

- ⑦-a `xcrun stapler validate` — 이미지에 공증 티켓이 동봉됐는지(네트워크 없이도 증명되는 증거).
- ⑦-b `spctl --assess --type open --context context:primary-signature` — macOS가 그 이미지를
  실제로 열어도 되는지 판정하게 하고 그 결과를 받습니다.

왜 필요한가: 종전 ①~⑥ 검사는 이미지 **안의 앱**만 평가했습니다. 앱이 온전해도 이미지 자신의
서명이나 공증 티켓이 빠지면 사용자 화면에서는 열리지 않습니다. 그 계급을 보는 검사가 없었습니다.
빌드 스크립트가 같은 평가를 하긴 하지만 그것은 빌드 직후 러너에서 만든 파일을 보는 것이고,
이 게이트는 업로드 **전**과 후처리(실제로 발행될 바이트)에서 다시 돕니다.

측정된 결과(2026-09-03): 이전 판 설치 이미지 2종(Apple Silicon·Intel)은 두 검사 모두 통과
(accepted · 공증 개발자 ID)이고, 서명·공증이 없는 합성 이미지는 두 검사 모두 거부됩니다. 이
음성 대조는 밀폐 테스트로 박아 두었으므로 "언제나 초록인 검사"가 아닙니다. 검사 결과는 CI 요약
페이지에도 승격되어, 태그 트리의 게이트가 구판이면 그 사실이 "미출력"으로 남습니다.

  의존할 때만 올리고, 두 발행 레인의 값은 항상 같아야 합니다. 판정 근거는 릴리스 기록에 남깁니다.

## 정직하게 — 이번 판의 한계

- **이전 판(v0.14.29)에 적어 둔 한계는 이번 티켓이 다루지 않은 항목에 한해 그대로 유효합니다** —
  동일 줄 동시 수정의 충돌, 병합 결과 검증이 JSON에만 걸리는 점, UTF-8로 읽히는 손상의 자동
  치유 공백, bin 형제 모듈의 혼재 창, 부트 내부 경로의 비트랜잭션성, 병합 캡처의 회수(GC) 부재,
  `cys init-pack` 훅 등록이 팩 환경 격리 밖이라는 점이 그렇습니다.
- **새 게이트 축의 강등 경로는 문안까지만 확인했습니다** — 러너 정책이 평가를 끌 수 있는 상태
  (assessments disabled)에서 ⑦-b가 건너뛰기 고지를 내는 경로는 주입 실행으로 재현하지 않았습니다.
  그 상태에서 게이트 전체가 "판정 불가"로 닫히는 계약 자체는 기존 테스트가 박고 있습니다.
- **CI 요약 승격은 문자열 배선까지만 검증했습니다** — GitHub 러너에서의 실제 요약 렌더는 태그
  레인에서만 관측됩니다.
- **Windows 실기 통합 검증 범위는 이전 판과 같습니다** — 태그 레인의 Windows 레그는 순수
  인메모리 병합 엔진·완전 초기화 계약·화면 필터만 실행하고, 파일시스템이 무거운 통합 검사는
  macOS 완전 레인에서만 돕니다. 이번 판의 게이트 변경은 macOS 전용 경로여서 Windows 산출물에는
  영향이 없습니다(버전 문자열 제외).
- 팩·데몬 수정(첫 절)의 검증 상태는 통합 시점에 이 문서에서 확정됩니다.

## 업그레이드하실 때 알아두실 것

- 팩 안 vendor 파일을 고쳐 쓰시던 분: 이전 판에서 도입된 보존(kept-drift) 계약이 그대로
  유지됩니다. 치유로 파킹된 수정본이 있으면 `cys pack-merge` 로 목록을 확인하고
  `cys pack-adopt --all` 로 복권하십시오.
- 부트 요약에 `kept-drift=K` 가 보이면 정상입니다 — 여러분의 수정이 제자리에 있다는 뜻입니다.
- 바이너리 버전이 올라간 판이므로, 디스크의 팩이 아직 이전 판이면 첫 부팅에서 팩 설치 스윕이
  한 번 돕니다(모든 바이너리 범프에서 동일한 동작입니다).

## Windows Defender / SmartScreen 안내 (유지)

Windows용 설치 파일은 Authenticode 서명이 없어(인증서 미보유) 실행 시 SmartScreen
"알 수 없는 게시자" 경고가 뜰 수 있습니다(**추가 정보 → 실행**으로 진행).
홈페이지의 `SHA256SUMS.txt` 와 대조해 무결성을 확인할 수 있습니다.
Defender 오탐은 WDSI 신고로 낮춰 갑니다(`docs/WDSI_SUBMISSION.md`).

### Defender가 `cys.exe` 를 격리한 경우 — 복구는 **순서**가 생명입니다

드물게 Defender의 행동 휴리스틱이 명령줄 실행 파일만 격리합니다.
GUI는 살아 있어 정상으로 보이지만 CLI가 사라져 팀이 서지 않습니다.

```powershell
# ① 제외 먼저 (복원 즉시 재격리 방지)
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\cys"

# ② 그 다음 복원
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Restore `
    -Name "Program:Win32/Contebrew.A!ml" -All
```

순서를 바꾸면 복원하자마자 다시 격리됩니다.
동봉 실행환경이 격리된 경우에도 시작할 때 빠진 파일과 복구 절차를 알려 줍니다.

## Windows 설치 전 — `claude` 는 따로 설치해야 합니다

프로그램은 대부분을 스스로 담고 있지만 `claude` 명령만은 예외입니다. PowerShell에서:

```powershell
irm https://claude.ai/install.ps1 | iex
```

git·node를 따로 깔 필요는 없습니다. 자세한 절차는 `docs/INSTALL-Windows-KR.md` 를 보시면 됩니다.

## macOS 설치

`.dmg` 를 열고 **"Install cys"** 를 더블클릭하면 설치가 원자적으로 끝납니다.
Apple 공증(notarization)을 마쳤으므로 "확인되지 않은 개발자" 차단 메시지는 나오지 않습니다.

- Apple Silicon: `cys_0.14.30_aarch64.dmg`
- Intel: `cys_0.14.30_x64.dmg`
