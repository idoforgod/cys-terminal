## 1. 팀 만들기 확인 창이 눌리지 않던 것

**증상**: Control Center 의 승인 Feed 카드에서 [확인 창 열기]를 누르면 창은 보이는데 [만들기]를 눌러도
아무 일이 없었습니다.

**원인**: 확인 창과 토스트의 겹침 순서(z-index)가 Control Center 패널보다 낮아, 보이는 것은 확인 창인데 클릭은
그 위의 투명한 패널이 받았습니다. 키 큰 창 위에 뜬 토스트도 같은 방식으로 클릭을 가로챘습니다.

**해법**: 겹침 순서를 한 표(층서 토큰)로 모으고 "확인 창·토스트는 패널보다 위" 관계를 검체로 못박았습니다.
실제 Chrome 렌더에서 수정 전에는 [만들기] 클릭이 패널에 먹히고, 수정 후에는 버튼에 닿는 것을 확인했습니다.
팀 카드에는 대화 경로 안내문이 조건부로 붙습니다(대화 승인이 가능한 자리에서만).

## 2. 대화로 팀 만들기 승인 (macOS·Linux)

대표(본부 master·CEO)가 제안을 올린 뒤 "이 내용으로 만들까요? **만들어**라고 말씀해 주시면 바로 만들겠습니다."라고
여쭈면, 그 창에 **직접** "만들어"(또는 "네"·"응"·"그래 만들어"·"승인" 같은 짧은 긍정)라고 치시면 됩니다.
그 한 번의 답에만 **한 번 쓰면 사라지는 생성 허가(1회용 토큰)** 가 나오고, 대표가 그것으로 팀을 만든 뒤
팀원 자리까지 이어서 띄웁니다. 화면 카드의 [확인 창 열기] → [만들기] 경로는 그대로 남아 있습니다.

**안전장치**
- 대표가 질문을 연 뒤 **5분 안의 첫 답** 하나만 봅니다. 부정·질문·조건이 섞인 답("예를 들면…?"·"만들지 마"·
  "나중에 만들어")이나 긴 문장은 승인으로 읽지 않습니다.
- 다른 에이전트가 보낸 문장(기계 배달)은 배달 기록과 대조해 걸러 내므로 승인이 되지 않습니다.
- 토큰은 **그 제안·그 창·그 본문**에만, **2분 안에 한 번** 유효합니다. 발급자는 훅(UserPromptSubmit)뿐이고,
  검증·소비는 데몬이 합니다. 토큰 없이 부서 생성 동사를 부르면 단일소유 가드가 종전처럼 거부합니다(`exit 7`).
- 승인 카드 정리(`cys feed reply … allow --team-token …`)는 **생성 성공 기록 뒤 30분 안**에만 됩니다.
- 적대 검토에서 찾은 위조 통로 4개(공개 발급 API 가 호출자 증거를 믿던 것 등)를 막았습니다.

**팀을 만든 뒤**: 종전에는 "부서장 전원 각성 → 첫 과제 → 보고"가 대표의 기억에 달려 있어 빠질 수 있었습니다.
이제 편성 도구가 결판(완결·일부·보류·실패)을 **이벤트로 1회씩** 알리고, 부서장에게 각성 지시를 한 번 보냅니다
(부서장 좌석에 에이전트가 관측됐을 때만 · 빈 자리는 깨우지도 기동하지도 않습니다). 대표는 그 턴에서
기다리지 않습니다 — 편성·각성은 비동기이고, 대표가 턴을 붙들면 회신이 큐에 적체되기 때문입니다.

**이 경로가 동작하지 않는 곳**(화면 경로로 안내합니다)
- **Windows**: 아직 대화 승인이 없습니다(`platform_gui_only`). 화면 카드로 만들어 주세요.
- 대표 지침을 병합하지 않은 기계(`directive_stale` — 맨 위 「먼저 하실 것」).
- 제안을 올린 자리가 바뀐 경우(`surface_not_publisher`).

## 3. 사이드바 사용량 — 모든 계정 · Antigravity · cys 창 밖 세션

**무엇이 빠졌었나**(원인 6가지를 실측으로 확인): 기본 `~/.claude` 프로필은 "어느 계정인지" 적힌 파일이 폴더
밖 `~/.claude.json` 에 있어 신원을 못 읽었고 · agy 는 실제 데이터 폴더(`~/.gemini/antigravity-cli`)가 아니라
예전 경로만 봤고 · 값이 아직 없는 계정은 화면에서 개수로만 접혔고 · 요금제 값이 비어 있는(plan null) 계정 처리가 빠졌고 · 부서 데몬
조회가 직렬이라 느렸고 · agy 포트 조회(`lsof`)가 조건을 잘못 묶었습니다.

**이제**
- 이 컴퓨터에서 찾은 계정이 **값이 없어도 한 줄씩** 나옵니다. 값이 없으면 `관측 전 · (이유)`, 읽는 길이
  고장났으면 `관측 실패 · (이유)` 로 구별합니다(0% 로 적지 않습니다).
- **Antigravity(agy)**: agy 1.2 부터 내부 서버가 쿼터 조회에 보안 토큰(CSRF)을 요구합니다. cys 는 그 토큰을
  읽지 않습니다(agy 로컬 기능 전체를 여는 열쇠이기 때문입니다). 대신 **agy 공식 상태줄 기능**으로 값을
  받습니다. macOS·Linux 에서는 설치·업데이트 때 `~/.gemini/antigravity-cli/settings.json` 의 `statusLine` 이
  **비어 있거나 없을 때만** cys 가 연결을 넣습니다(표지 `--cys-autolink` · 직접 넣은 설정은 덮지 않습니다).
  이미 떠 있는 agy 는 다시 켜야 적용될 수 있습니다.
- **cys 창 밖(외부 터미널) Claude 세션**: 상태줄이 cys 로 연결된 프로필이면 그 계정 줄에 값이 모입니다
  (`usage.report_account`). 데몬을 새로 띄우지 않고 0.4초 안에 닿지 않으면 그 한 번은 버립니다.
  **창 밖 값은 표시용입니다** — 계정 한도 경보(80%·95%)의 근거로 쓰지 않습니다. 이 구분은 오판 방지 장치이지
  보안 경계가 아닙니다(USER-MANUAL §4 「집계 범위」에 한계를 적었습니다).
- 좌석 상태줄 보고가 데몬이 멈춘 동안 **최대 40초 기다리며 데몬을 새로 띄우려던** 것을 없앴습니다 — 이제
  데몬을 띄우지 않고 1초(Windows 2초) 안에 포기합니다(실측 40.01s → 1.01s). 데몬이 멈춘 동안 상태줄마다
  cys 프로세스가 쌓이던 경로가 닫혔습니다.

### 5-1. clear 가드 v3 한눈에 — 무엇이 바뀌었고 무엇을 알아야 하나

없습니다.

**상한(폭주 없음).**
- 좌석당 통보 사이 최소 10분 → **시간당 ≤ 6회 · 24시간 ≤ 144회**.
- 같은 통보의 재배달은 1회(새 통보가 아닙니다). 통보 1건당 사이클은 최대 2회(clear 는 나갔으나 실효를 보지 못한 rc 80 뒤의 복구 1회).
- `--detach` 작업: 좌석당 하나 · 일반 좌석 동시 2 · 우선 좌석(master·CEO·CSO) 동시 3 · 전체 5 · 대기 16 · 630초 강제 종료 · 데몬은
  스스로 사이클을 열지 않습니다.
- 경보 라우터: master·CEO clear 신호는 시간당 26건 몫 · 그 밖의 경보 20건 몫 · 합산 46 < CSO 큐 보호선 50.

**영구 정지 없음.** 효과 없는 통보(사이클 뒤 곧바로 압축 · 사이클 없이 재통보 · 차단점 이상 값의 고착 자기보고)는 다음 통보를
15·30·60·120분(상한) 미룰 뿐이고, 사이클이 끝나면 미룸도 끝납니다. 종전 가드의 '자동 clear 정지' 상태는 없어졌습니다.

**유휴 무발화.** 다음 통보는 사이클 뒤 10분 동안 잰 수준보다 5%p 이상 자라야 납니다(200K 막대 = max(기본 임계, min(수준 + 5,
max(85, 수준 + 1), 88))). 그래서 일하지 않는 대표는 다시 통보받지 않습니다. 명시 예외: ⓐ 데몬 재기동 뒤 첫 관측(기본 임계) ·
ⓑ 가장자리(아래) · ⓒ 압축 뒤 잰 수준이 88% 이상(C 띠) · ⓓ 손 `/clear`·재기동처럼 표지 없는 clear · ⓔ 자기보고 간격이 압축
주기보다 길 때의 표본 착오.

**자동 압축을 끈 200K 좌석의 가장자리 예외와 처방.** Claude Code 는 200K 창에서 83.5% 에 스스로 압축하고 88.5% 에서 입력을
막습니다(자동 압축을 끄면 앞의 압축이 없습니다). 그래서 사이클 뒤 10분 안 또는 그 창 뒤 첫 보고가 85%(1M 96%) 이상이면 수준에
넣지 않고 곧바로 판정합니다(차단점 전의 저장 기회). 대가: 복원·붙잡혔던 회신만으로 매 사이클 85% 이상으로 돌아오는 좌석은
10분마다 clear 될 수 있습니다(시간당 ≤ 6 · 오너 결재 대기 §9-9 ①). **처방**(오너 feed 에 같이 실립니다): 그 좌석의 자동 압축
켜기 · 1M 창 모델 · 지침 축소 · 자기보고 좌석이면 자기보고 정정 또는 실측(상태줄) 축 확보. 착지가 차단점에 0.1~0.2%p 까지
붙는 좌석은 이 예외로도 지켜지지 않을 수 있습니다(§9-14).

**오너에게 오는 경보.**
- `context.edge_return`(가장자리·C 띠 복귀) — error feed 는 고리 회차의 1·2·4·8·16…번째만(좌석당 24시간 ≤ 8건).
- `context.clear_ineffective`(효과 없음) — feed 는 효과 없음 회차의 1·2·4·8…번째만(첫 번째 warn · 연속 2번째부터 error · 좌석당 24시간 ≤ 8건).
- `context.level_measured`(사이클 뒤 수준이 기본 임계보다 높거나 가장자리) — warn feed 좌석당 6시간 1회.
- 5분 진행 보고: 미해결 clear 통보가 10분 넘게 집행되지 않으면 fire id·경과·`--fire` 처방 한 줄(가드가 있는 좌석에는 고정 60% 경보를
  더 띄우지 않습니다 · 구 데몬 좌석은 종전 60%).
- 회차·24시간 수는 **데몬 세대 안의 수**입니다(가드 기록은 휘발 — 재기동 뒤 0부터 · feed 제목에 '데몬 기동 뒤 N시간치').

**집행: `cys cycle-agent`.**
- 통보마다 번호(`fire_id` · 경보 요약 `fire=<id>`)가 붙고 `--fire <id>` 로 넘깁니다 — 데몬이 그 통보 뒤 사이클이 이미 끝났는지
  판정해 같은 통보의 중복 clear 를 막습니다.
- 1콜은 점유 대기를 포함해 **단일 전체 시한 570초** 안에 끝납니다(Claude Code Bash 도구 상한 600초 − 여유 30 · clear 전 단계는
  clear 뒤 확인·재주입 몫 180초를 남긴 시각에서 멈춤 · 데몬이 응답하는 가정 — 데몬이 굳으면 RPC 한 번이 무진행 상한 40초까지 더).
- 종료 코드: 0 clear 실효 확인·재주입 완료 · 80 clear 를 보냈으나 실효 미관측(재주입 0건 · 통보 미해결) · 81 실효 측정 불능 ·
  82/83 검증자 충돌·미해소(송신 0건) · 84 대상이 유휴가 되지 않음 · 85 사람 초안 보호(84·85 는 clear 송신 0건) · **86** clear 는
  발효했고 재주입만 보류 — 손으로 다시 clear 하지 말 것(종전부터) · **87** 건너뜀 — 그 통보 뒤 사이클이 이미 끝남(송신 0건 · 재집행
  금지 · 새) · **88** 다른 집행자의 사이클이 진행 중(송신 0건 · 이미 처리됨이 아님 — 기다리지 말고 턴을 끝냄 · 재배달이 오면 같은
  `--fire` · 새) · **89** `--detach` 접수(새).

**집행 방식(수정 6회차 · 발행 전 게이트 수정 1·2회차).**
- clear 집행 거버넌스는 그대로입니다 — self-clear 금지 · clear 는 master↔CSO 상호 집행 · 결정(어느 좌석·어느 통보·검증자)은
  CSO 또는 대표의 1콜이 합니다.
- CSO 는 그 1콜을 `--detach` 로 냅니다. CLI 는 사전검사 뒤 데몬에 접수만 하고 곧바로 rc 89 로 돌아오며, 데몬이 같은 1콜을 자식(형제
  `cys` CLI)으로 띄워 부른 좌석의 신원으로 끝까지 붙들고, 끝나면 `[cycle-result] surface:<id>(<역할>) fire=<id> rc=<N> — <뜻> · … ·
  사유: <1줄>` 을 부른 좌석의 큐로 한 번 보냅니다. CSO 가 한 좌석의 1콜을 턴 안에서 기다리는 동안 다른 좌석(자동 압축을 끈 대표)의
  통보가 줄에서 기다리던 경로를 구조로 없앴습니다.
- 대표(master·CEO)도 워커와 CSO 좌석의 사이클을 `--detach` 로 냅니다 — 데몬이 붙들므로 대표가 CSO 에게 clear 돼도 끊기지 않고,
  CSO 는 데몬이 붙든 작업을 대표 clear 보류 사유로 보지 않습니다(보류 사유는 데몬 밖 동기 1콜뿐).
- 데몬 작업표의 우선 좌석(역할 맵이 master·CEO·CSO 로 가리키는 좌석)은 따로 3칸이라 다른 좌석 1콜 뒤에서 기다리지 않습니다.
  워커는 일반 2칸에서 차례를 기다립니다(§9-9).
- 시한·점유·잠금·표지 나이는 데몬 단조 시계로 잽니다(자식의 570초 시한과 같은 시계 — 랩톱 절전을 가로질러도 산 사이클을 죽이지
  않습니다).
- 구 데몬이면 `--detach` 는 rc 1('이 데몬은 --detach 를 모른다') — CSO 는 동기 1콜(Bash timeout 600000 · 전경), 대표는 백그라운드
  동기 1콜로 되돌아갑니다(CLI 가 스스로 바꾸지 않습니다).

**되돌리기.** clear 가드 v3 와 `--detach` 에는 **끄는 노브가 없습니다**(`CYS_CONTEXT_THRESHOLD_PCT` 는 기준 임계만 바꿉니다).
- `--detach` 만 피하려면: 지침에서 `--detach` 를 빼고 동기 1콜로 부르면 됩니다(데몬은 동기 1콜도 그대로 받습니다 · CSO 는 Bash
  timeout 600000 전경 · 대표는 백그라운드). 그러면 위 '줄에서 기다림' 경로가 돌아옵니다.
- 가장자리 고리가 부담인 좌석은 좌석 쪽에서: 자동 압축 켜기 · 1M 창 모델(1M 에서 가장자리는 96%).
- 판 전체: §6 의 본체 재설치 — 이때 **병합한 MASTER·CSO 지침에서 `--fire`·`--detach` 도 함께 빼야 합니다**(v0.14.41 CLI 는 두
  플래그를 몰라 rc 2 로 끝납니다 · §6).

**검증 요지.** 좌석 모형(운영 코드 발췌를 그대로 붙인 순수 상태기계): 설계 핀 31/31 · 무작위 성질 10만 씨앗 전부 성립(최소 간격
600.0초 · 굴림 1시간 ≤ 6 · 영구 무clear 0 · 막대 아래 발화 0) · 6시간/24시간 설계 스윕 · 반례 격자. 실 바이너리 드릴(release · 가짜
에이전트 · 좌석 1~6 · 최장 2시간 · 지침 병합 뒤): 설계 경계 안 차단점 위 0초(§9-14 의 칼날 모양 셋 제외) · 대표 경보 → 1콜 시작
5.0초(②통보 → ack 30초를 넣은 판 35초) · CSO 좌석 1콜 시작 7.0초 · 1콜 최악 528.6초. 실제 Claude 좌석과 Windows 실기 확인은
아직입니다(§9-11 · §11).

- 발행 전 게이트 수정 1회차(시계 · 경보 라우터 몫 · 복귀 feed · 지침)는 **운영체제 공통**입니다. 시한·점유·잠금·표지 나이는
  Rust `Instant`(Windows 는 QueryPerformanceCounter)로 재고 자식 cycle-agent 도 같은 `Instant` 라, 그 시계가 절전을 세든 안
  세든 데몬과 자식이 같은 시계를 봅니다(벽시계는 판정 입력이 아닙니다 · cfg 분기 0). 교차 타입체크로 확인했고 Windows 실기
  확인은 아직입니다.
- 발행 전 게이트 수정 2회차(사이클 작업표 우선 좌석 · 지침 문면)도 **운영체제 공통**입니다 — 입장 판정은 순수 함수이고 우선 좌석 판정은
  역할 맵 조회뿐입니다(cfg 분기 0). 교차 타입체크 오류 0 · 경고 29(직전과 같은 목록)로 확인했고 Windows 실기 확인은 아직입니다.
- **`cycle-agent --detach`(수정 6회차)는 Windows 에서 새 런타임 경로입니다** — 데몬(`cysd.exe`)이 같은 폴더의 `cys.exe` 를 창 숨김
  (`CREATE_NO_WINDOW` · 분리 없음)으로 자식으로 띄우고, 파이프 stdin 에 `go` 한 줄을 쓰고, 명명 파이프 상대 pid(= 자식 pid)에 요청 좌석의
  신원을 위임하고, 630초가 지나도 살아 있으면 `TerminateProcess` 로 끝냅니다. 교차 타입체크(오류 0 · 새 줄 경고 0)와 코드 검토만 했고
  **Windows 실기 확인은 아직**입니다(발행 뒤 확인 목록: detach 접수 → 자식 기동 → `[cycle-result]` 배달). Windows 의 사이클 점유·주입
  잠금 점유자 생존 판정은 pid 만 보고 프로세스 시작 시각은 보지 않아, 해제 없이 죽은 점유가 pid 재사용으로 최대 1200초·15초 늦게
  풀릴 수 있습니다(늦게 푸는 방향 · 중복 clear 쪽이 아님). Windows 의 `Instant`(QueryPerformanceCounter)가 절전을 세는지와 무관하게
  데몬과 자식은 같은 시계를 봅니다.
- 채널 메시지 간격 빈틈 수정(§4 · §9-12)은 **Windows 에도 똑같이 적용됩니다** — 좌석 writer 는 운영체제 공통 경로이고
  수정은 채널이 넘긴 시각 기록 하나뿐입니다(쓰는 바이트 무변경). 교차 타입체크 오류 0 으로 확인했고 실기 확인은 아직입니다.
- `docs/WDSI_SUBMISSION.md` 의 절차는 그대로입니다 — 바이너리 해시가 바뀌므로 이전 판정은 이번 빌드에 적용되지
  않습니다.
