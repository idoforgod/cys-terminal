# v0.14.29 — 여러분이 고친 파일을 업데이트가 조용히 되돌리지 않습니다

지난 판까지 팩(pack) 안의 출하(vendor) 파일을 여러분이 고치면, 다음 부트의 설치 스윕이
그 수정을 **조용히 vendor 본으로 되돌렸습니다**(자동 치유). 2026-08-30 실사고에서 확장 10건
(스킬 4·훅 4·내부 도구 2)이 이 경로로 파킹·비활성화됐습니다 — 전부 정당한 사용자 확장이었습니다.
이번 판은 그 계약 자체를 뒤집습니다: **벤더가 안 바꾼 파일의 수정은 제자리에 보존되고(kept-drift),
벤더가 바꾸면 자동으로 병합되며, 충돌해도 바이트 하나 잃지 않습니다.**

---

## 1. [계약 전환] 자가치유가 3계층으로 재정의됐습니다

종전의 "수정된 system 파일은 임베드로 치유"라는 단일 규칙(P0-4)이 3계층으로 갈라졌습니다.

- **계층 1 — 무조건 자동**: 파일이 **없으면** 다시 만들어 놓습니다. **읽을 수 없으면**(비UTF-8
  손상 등) **바이트 그대로 백업한 뒤** 치유하고, 백업조차 안 되면 덮지 않고 무접촉 보존 + 경고합니다
  (격리 `quarantined`). 보안 잠금 파일(`trusted-keys.json`)의 모든 드리프트는 즉시 치유합니다
  (수정=변조 신호 — `.user` 백업 동반).
- **계층 2 — 벤더 전진 시 자동**: 벤더가 그 파일을 실제로 바꿨을 때만 자동 병합이 돌고,
  병합 충돌·검증 게이트 실패면 vendor 본을 채택하되 수정본을 보존합니다 — "임베드 진실"이
  화해 시점마다 재확립됩니다.
- **계층 3 — 명시 동사만**: **벤더 무변경 + 읽을 수 있는 드리프트**는 더 이상 자동으로 건드리지
  않습니다. 제자리 보존(kept-drift) + `cys doctor` 라벨 + 되돌리고 싶을 때만 `cys pack-heal` /
  `pack-merge --take-new` / `--force`(전량 · `.user` 백업 동반)입니다.

이 축소의 정직한 계량(전부 실측): 현 라이브 팩 System 드리프트 **0/447건** · 역대 기록된
System 드리프트 10건(이번 사건)은 **전원 사용자 확장 = 치유가 해를 끼친 대상** · 즉 이 한
클래스에서 자동 치유는 역사적으로 이익보다 해가 컸습니다.

계약 핀도 몰래 바꾸지 않았습니다. 종전 계약의 박제였던 테스트
(`install_staged_preserves_user_edit` — "system 파일 편집은 임베드로 강제 갱신")는 후계 2본으로
명시 분해됐습니다: ⓐ 벤더 전진 시 치유+백업 불변(`system_edit_healed_when_vendor_advanced`)
ⓑ 벤더 미전진 시 kept-drift+원장(`system_edit_kept_when_vendor_static`).

"배포 스큐 동결이 재발하는 것 아니냐"는 반론에는: 종전 동결은 vendor 전진분도 못 받는
정지였으나, 본 설계는 전진분을 **반드시 병합 수용**합니다(스큐 없음).

## 2. 벤더 미전진 보존 (kept-drift) — 수정이 제자리에 남습니다

벤더가 안 바꾼 파일의 여러분 수정은 이제 **파일 그 자리에 그대로** 남습니다. 부트 요약 1줄
(`pack: … kept-drift=K …`)과 병합 원장, `cys pack-plan` 버킷, `cys doctor` 가 그 사실을
보여줍니다. 팩 안 vendor 파일을 편집할 때 뜨는 경고(pack-guard)도 같은 내용으로 정정했습니다 —
종전 문구는 "다음 부트 스윕에 치유됩니다"라고 약속했는데, 이 판부터 그 약속은 거짓이기 때문입니다.

## 3. 벤더가 전진하면 자동 3-way 병합 (검증된 조상 · 순수 Rust)

- 병합의 조상(base)은 **검증된 것만** 씁니다: 설치 당시 원본 사본(`.pristine`)의 해시가
  매니페스트와 일치할 때만 병합을 시도하고, 아니면 종전 거동(치유+보존)으로 안전하게 낙하합니다.
- 병합 엔진은 **diffy 0.5.1 순수 Rust** 입니다(하한 고정 사유: 0.5.0에는 무개행 말미 충돌
  마커가 본문 줄에 접합되는 버그 #85). 외부 `diff3` 셸아웃은 소멸했습니다 — PATH 미주입
  맥락의 잔존 실패와 macOS(BSD)·GNU 구현 차 비결정론이 함께 사라집니다.
- **충돌 판정이 GNU diff3 보다 보수적인 방향은 안전측입니다**: 충돌 = vendor 본 + 수정본
  보존 = 손실 0. 병합 전에 수정본 전문을 팩 밖 캡처 디렉터리에 저장하고, 캡처가 안 되면
  병합을 시도조차 하지 않습니다.
- 병합 결과 검증 게이트: `*.json` 은 파스가 깨지면 병합을 버리고 안전 낙하합니다. 순삭제
  과반 등 손상 의심 휴리스틱도 같은 자리에서 겁니다.
- 대화형 `cys pack-merge` 경로도 **같은 엔진으로 통일**했습니다(이중 의미론 제거).

## 4. 복구 동사 3종 + `cys doctor` 의 pack-drift 항목

- **`cys pack-adopt [<rel> | --all | --from <경로>]`** — 치유로 파킹된 수정본(`.user`)을
  원클릭 복권합니다. 2026-08-30 사건 10건 복구의 도구화입니다. 벤더가 이미 전진해 있으면
  기본은 착수 거부(+`--merge-after` 옵트인)라 "복원했더니 또 바뀌는" 침묵 사건이 없습니다.
  원장에 없는 파일(예: 로컬로 옮겨 둔 사용자본)은 `--from` 명시 소스로 같은 검증 파이프라인을
  탑니다.
- **`cys pack-heal <rel>`** — 명시 치유(vendor 본 복원). 백업 선행 · 병합 결과를 손상으로
  오인한 자기 소거를 막는 확인 프롬프트가 있습니다.
- **`cys pack-merge --revert-merge <rel>`** — 자동 병합의 1명령 가역화(디스크=캡처 원본).
- **`cys doctor` 신설 `pack-drift`(읽기전용)** — 드리프트 건수 + 원장 kind 계상 + 손상 의심
  라벨. 자동 행동은 없습니다(오판 시 손실 방향이기 때문).

## 5. 판독 불가 파일도 백업 없이 덮지 않습니다

비UTF-8 손상 등으로 읽을 수 없는 파일은 종전엔 무백업으로 치유되는 유일한 edge 였습니다.
이제 **바이트 그대로 백업한 뒤** 치유하고, 백업이 안 되면 격리(`quarantined`)로 무접촉
보존합니다 — 백업 없이는 덮지 않습니다.

## 6. [수리] 부트 건강성 계측 앵커 2건 (U19/U29)

GUI 리팩터(봉인 조립점)로 낡아진 건강성 검체 앵커 2건을 실체 리터럴로 추종했습니다 —
검사 의도·강도는 동일합니다(need 메시지 불변).

## 정직하게 — 이번 판의 한계

- **동일 줄 동시 수정은 여전히 충돌합니다** — 병합의 본질입니다. 보장은 충돌 시에도 손실 0
  (vendor 본+`.user`+`.base`+캡처) + 가시화 + `pack-adopt`/`--revert-merge` 가역입니다.
- **clean-but-wrong 병합의 게이트는 `*.json` 뿐입니다** — `.sh`/`.py` 문법 검증은 Windows
  비가용·외부 바이너리 0 원칙상 도입하지 않았습니다. 완화: 캡처+`--revert-merge` 즉시 복구+부트 고지.
- **UTF-8 로 읽히는 잘림·오염은 두 조합에서 자동 치유되지 않습니다** — ⓐ 벤더 무변경이면
  kept-drift 보존(사용자 수정과 문자적으로 구별 불가) ⓑ 벤더가 손상 영역 **밖만** 전진한
  조합은 손상이 '사용자 삭제'로 clean 병합될 수 있습니다(순삭제 휴리스틱이 조준 방어하되
  완전하지 않음 · 캡처로 바이트 손실은 0). 실측 노출 0/447 이 이 트레이드의 근거입니다.
- **bin 형제 모듈의 mixed-version 창** — 사용자가 bin 한 파일만 고치고 벤더가 형제를
  전진시키면 세트 비일관이 가능합니다. doctor 가 bin 계열을 별도 카운트로 표시하며, 세트
  일관성 게이트는 0.14.30 후보입니다.
- **부트 in-place 경로는 여전히 비트랜잭션입니다** — 파일별 원자 쓰기+수렴 증명으로 손실 0은
  보장하나 저널화 자체는 0.14.30 과제입니다.
- **mixed-EOL 은 자동 병합 효용이 0 입니다** — base 가 LF 인 파일을 CRLF 로 재저장하면 벤더
  전진 시 전 파일 충돌→치유 강등이 구조적으로 반복됩니다(손실 0이나 Windows 체감 직격).
  병합 전 EOL 정규화는 바이트 보존 원칙과 긴장하는 설계 변경이라 0.14.30 오너 결정 사항입니다.
- **새 보존·병합 실행 경로의 Windows 실기 통합 검증은 엔진 단위까지입니다** — 태그 레인의
  Windows 레그는 `merge3::`(순수 인메모리 엔진)·factory_reset·alt_screen 필터만 실행하고,
  kept-drift 보존·Merge3 실행부(install 스윕)·바이트 백업 등 fs-heavy 통합 핀은 macOS 완전
  레인에서만 돕니다(신거동 코드의 플랫폼 분기 0 · Windows 항목은 위 mixed-EOL 실측뿐 —
  실기 통합 검증 범위의 정직한 기재).
- **User 9건·SeedOnce 4건은 자동 병합 밖입니다** — soul.md·CLAUDE.md·디렉티브·schedule.json
  등은 현행 `.new` 병치+수동 `pack-merge` 유지(헌법 파일 자동 병합 금지), memory/·round 상태는
  불가침입니다. **현 라이브 팩의 드리프트 5건이 전부 이 영역**이므로, "수정 파일 자동 병합"의
  실사용 체감은 System 확장이 발생한 설치본부터 나타납니다.
- **캡처 GC 는 아직 없습니다**(0.14.30) — 병합 캡처는 쌓이기만 합니다(팩 밖 디렉터리).
- **`cys init-pack` 의 훅 등록 대상은 팩 env 격리 밖입니다**(0.14.30) — `CYS_PACK_DIR`/
  `CYS_CONFIG_DIR`/`CYS_PACK_CAPTURES_DIR` 를 스크래치로 격리해도 각성 훅은 `dirs::home_dir()` 로
  찾은 실 `~/.claude*/settings.json` 에 등록됩니다(데몬 경로 병합의 비기본 팩 스킵 게이트가 CLI
  대상 탐색엔 없음). 그때까지 빌드 바이너리 E2E 는 **HOME 샌드박스가 필수**입니다(CONTRIBUTING
  'E2E isolation — HOME sandbox (W0-E2E)' · 2026-08-31 실측: 미샌드박스 검증 라운드가 실사용
  프로필 4본에 죽은 스크래치 훅 3쌍씩을 누적 → `cys hooks-prune` 으로 정리). CLI 경로에 동일
  게이트 이식이 0.14.30 후보입니다.
- **phoenix 디스크 폴백** — 부활 도구의 디스크 폴백 경로는 해당 bin 파일이 kept-drift 상태면
  비활성입니다(임베드 1차 경로는 무영향 · fail-closed 통지).
- **구 바이너리와 팩 하한(min_binary)** — 이 판의 팩은 두 레인(`PACK_MIN_BINARY`·
  `PACK_MIN_BINARY_OVERRIDE`) 모두 하한 0.14.29 로 서명됩니다(v0.14.29 태그 **전** 동시 상향
  완료). 구 바이너리(≤0.14.28)의 스윕은 종전대로 치유하므로 하한을 올리지 않으면 kept-drift
  보존 약속이 그곳에서 거짓이 되기 때문입니다. 그 대가로 ≤0.14.28 바이너리는 이 팩을 무중단
  팩 채널로 받지 못하고 바이너리 업데이트 전까지 종전 팩에 머뭅니다(잘못된 약속 배송보다 안전측).

## 업그레이드하실 때 알아두실 것

- 팩 안 vendor 파일을 고쳐 쓰시던 분: 이번 판부터 그 수정이 **보존**됩니다. 이전 판에서
  치유로 파킹된 수정본(`<파일>.user`)이 있다면 `cys pack-merge` 로 목록을 확인하고
  `cys pack-adopt --all` 로 복권하십시오.
- 부트 요약에 `kept-drift=K` 가 보이면 정상입니다 — 여러분의 수정이 제자리에 있다는 뜻입니다.
- 자동 병합이 마음에 안 들면 `cys pack-merge --revert-merge <파일>` 로 1명령 되돌립니다.

## Windows Defender / SmartScreen 안내 (유지)

Windows용 설치 파일은 Authenticode 서명이 없어(인증서 미보유) 실행 시 SmartScreen
"알 수 없는 게시자" 경고가 뜰 수 있습니다(**추가 정보 → 실행**으로 진행).
홈페이지의 `SHA256SUMS.txt` 와 대조해 무결성을 확인할 수 있습니다.
Defender 오탐은 WDSI 신고로 낮춰 갑니다(`docs/WDSI_SUBMISSION.md`).

### Defender가 `cys.exe` 를 격리한 경우 — 복구는 **순서**가 생명입니다

드물게 Defender의 행동 휴리스틱이 명령줄 실행 파일만 격리합니다.
GUI는 살아 있어 정상으로 보이지만 CLI가 사라져 팀이 서지 않습니다.

```powershell
# ① 제외 먼저 (복원 즉시 재격리 방지)
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\cys"

# ② 그 다음 복원
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Restore `
    -Name "Program:Win32/Contebrew.A!ml" -All
```

순서를 바꾸면 복원하자마자 다시 격리됩니다.
동봉 실행환경이 격리된 경우에도 시작할 때 빠진 파일과 복구 절차를 알려 줍니다.
