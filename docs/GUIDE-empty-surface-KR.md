# 빈 창(빈 surface) 사용 설명서

> **누구를 위한 문서인가**: cys 터미널을 처음 쓰는 분.
> **무엇을 설명하나**: 화면에 남는 "아무것도 없는 창" 하나가 무엇이고, 무엇을 할 수 있고, 무엇은 못 하는지.
> **읽는 데 걸리는 시간**: 5분. 급하면 맨 아래 [한 장 요약](#한-장-요약)만 보셔도 됩니다.

---

## 1. 이 창은 무엇인가요?

cys를 쓰다 보면 — 특히 **업데이트를 하고 나면** — 화면에 이런 창이 하나 남습니다.

```
user@MacBook-Pro ~ %
```

AI 직원(마스터·워커·감사 등)이 앉아 있지 않은, **그냥 검은 화면에 프롬프트만 있는 창**입니다.

### 고장이 아닙니다

이 창은 **당신이 상단의 `+ New` 버튼을 눌러 만드는 창과 완전히 똑같은 물건**입니다. 프로그램 내부적으로도 같은 방식으로 만들어집니다. 특별히 이상한 게 생긴 게 아니라, **빈 책상 하나가 놓여 있는 것**입니다.

### 비유로 이해하기

cys를 회사라고 생각해 보세요.

| 화면의 창 | 회사로 치면 |
|---|---|
| master 창 | 비서실장 책상 |
| worker 창 | 실무자 책상 |
| reviewer 창 2개 | 감사 책상 |
| **아무도 없는 빈 창** | **주인이 정해지지 않은 예비 책상** |

회의실에 있는 그 책상 — 손님이 앉기도 하고, 출장 갔던 직원이 돌아와 쓰기도 하고, 평소엔 사장님이 서류 볼 때 쓰는 그 책상입니다.

### 왜 생기나요?

업데이트를 하면 프로그램이 다시 시작되고, AI 직원들이 하나씩 되살아납니다(피닉스 복원). 그런데 **직원들이 돌아오기 전에 화면이 먼저 열립니다.** 화면이 텅 비어 있으면 사용자가 당황하므로, cys는 **일단 빈 책상 하나를 놓아둡니다.** 그 뒤에 직원들이 돌아와 옆에 앉는 것이죠.

그래서 남습니다. **버그가 아니라 배려입니다.**

---

## 2. 지워야 하나요? — 아니요, 쓸 곳이 있습니다

이 창은 **회사에서 유일하게 "사람 자리"입니다.** 나머지 네 창은 전부 AI의 자리고요.

cys의 사규(directives)에는 이런 문장이 실제로 적혀 있습니다.

> "오너는 cys 역할 노드가 아니다."
> — 사장님은 직원 명단에 없다는 뜻입니다.

맞는 말인데, 지금까지 **사장님이 앉을 자리도 없었습니다.** 그래서 사장님은 비서실장(master) 책상에 걸터앉아 명령을 내려왔습니다.

**이 빈 창을 당신의 자리로 쓰세요.**

### 제일 먼저 할 일 — 이름 붙이기 (30초)

1. 그 창의 **제목 줄(맨 위 회색 띠)** 에서 **마우스 오른쪽 클릭**
2. **[이름 변경]** 클릭
3. `◆ 내 자리` 라고 입력하고 **Enter**

이제 그 창은 "정체불명의 빈 창"이 아니라 **당신의 책상**입니다. 프로그램을 고치는 게 아니라 이름표만 붙이는 것이라 아무 위험이 없습니다.

## 3. 이 자리에서 할 수 있는 일

아래 명령들은 그 창에 **그대로 타이핑하고 Enter**를 치면 됩니다.

### 🚨 급할 때 — 전부 멈추기

AI들이 이상한 방향으로 달려갈 때, 여기가 **비상 브레이크**입니다.

```bash
cys pause      # 전 직원의 대기 작업·예약 작업을 얼립니다
cys resume     # 다시 풀기
```

> 💡 `pause`는 **컴퓨터를 껐다 켜도 계속 멈춘 상태로 유지**됩니다. 안심하고 눌러도 됩니다.

### 👀 지금 무슨 일이 벌어지는지 보기

```bash
cys status              # 전 직원 현황 한눈에
cys fleet               # 모든 부서·직원이 지금 무슨 일을 하는지
cys events --reconnect  # 회사에서 일어나는 일이 실시간으로 흘러갑니다 (멈추려면 Ctrl+C)
```

> 💡 마지막 명령은 **켜두는 걸 권합니다.** 이유는 [5장 주의사항](#5-알아두면-좋은-주의사항-4가지)에 있습니다.

### ✋ 잘못 내린 지시 되돌리기

```bash
cys queue list    # 아직 배달 안 된 지시 목록
cys queue clear   # 전부 취소
```

### ✅ 결재하기

AI가 "이거 해도 될까요?" 하고 올린 요청을 승인/거부합니다.

```bash
cys feed list                          # 결재 대기 목록
cys feed reply <번호> allow            # 승인
cys feed reply <번호> deny             # 반려
```

> 💡 **이 자리는 결재가 반려당하지 않는 유일한 자리**입니다. cys에는 "자기가 올린 서류는 자기가 결재 못 한다"는 규칙이 있는데, 당신은 서류를 올리지 않으니까요.

### 🔧 직원이 죽었을 때 되살리기

```bash
cys restore --include-master   # 죽은 직원들을 되살립니다
cys drain --verify             # 재시작 전에 "저장 다 했는지" 확인
```

### 🔍 직접 확인하기

AI가 "다 했습니다"라고 보고했을 때, **당신이 직접 확인하는 자리**입니다.

```bash
git diff             # 진짜 뭘 고쳤는지 내 눈으로
cys recall <검색어>   # 과거 대화 기록 검색
```

> 💡 cys의 원칙 중에 *"'될 것이다'가 아니라 '확인했다'로 보고한다"* 가 있습니다. 사장님에게도 확인할 책상이 필요합니다.

### 🗣️ 직원에게 말 걸기

```bash
cys send --to master "상황 보고해줘"
cys send-key --to master Return          # 위 명령 다음에 이걸 쳐야 전송됩니다
```

> ⚠️ 본문에 백틱(`` ` ``)이나 `$(...)`·`$변수`가 섞여 있으면 **큰따옴표 안이라도 셸이 먼저
> 실행·치환**합니다(실제로 직원 역할이 바뀐 사고가 있었습니다). 그럴 땐 아래처럼 보내세요.
>
> ```bash
> cys send --to master --stdin <<'EOF'
> [보고] `이 백틱은 실행되지 않습니다` $HOME 도 그대로 갑니다
> EOF
> ```
>
> 파일에 적어 두고 `cys send --to master --file 본문.txt` 로 보내도 됩니다.

> 💡 **이 자리는 다섯 직원 누구에게든 말을 걸 수 있는 유일한 자리**입니다. (감사는 실무자에게 직접 말을 못 겁니다. 규칙으로 막혀 있죠.)

## 4. 이 자리에서 **할 수 없는** 일 — 딱 3가지

정직하게 알려드립니다. 실제로 명령을 실행해서 확인한 결과입니다.

### ❌ 1. 인감 찍기 (`cys approval sign`)

위험한 명령을 미리 허가해두는 "도장"은 **비서실장(master) 자리에서만** 찍힙니다.

```
실행 결과: "master role surface에서만 허용 — 위조 서명 차단"
```

**대신 이렇게**: master 창에 가서 찍거나, master에게 시키세요.

### ❌ 2. 장부에 등록되는 실행 (`cys run`)

오래 도는 프로그램(서버 등)을 회사 장부에 올려 "끝나면 자동 정리"되게 하는 기능입니다.

```
실행 결과: "capability denied: lacks 'write-shell' (deny-by-default)"
```

이 자리는 명찰이 없어서 권한이 0입니다. **이건 뚫지 않는 게 좋습니다** — "명찰 없으면 권한 없음" 규칙에 구멍을 내면 다른 것도 통과하게 되니까요.

**대신 이렇게**: 짧은 명령은 그냥 실행하세요(문제없습니다). 서버처럼 오래 도는 건 원래 AI 직원에게 시키는 게 맞습니다.

### ❌ 3. 이름으로 불리기

```
cys send --to owner "..." 실행 결과: "no surface registered for role 'owner'"
```

이 자리는 명찰이 없어서 **아무도 당신을 호출할 수 없습니다.**

**이건 오히려 장점입니다.** 이 자리는 **어떤 AI도 차지할 수 없고**(자리 뺏기는 명찰 있는 자리끼리만 일어납니다), **부활 시스템이 건드리지도 않습니다**(살아 있는 창은 절대 손대지 않는다고 코드에 명시돼 있습니다). 완전히 당신 것입니다.

## 5. 알아두면 좋은 주의사항 4가지

### ⚠️ 1. 5분 조용하면 AI가 "쓰러졌나?" 하고 찾아옵니다

cys의 살림 담당(CSO)에게는 *"5분간 아무 기척 없는 창은 확인하고, 멈춘 것 같으면 깨워라"* 라는 임무가 있습니다. 좋은 규칙이지만, **당신이 커피 마시러 간 것도 "멈춤"으로 보입니다.**

**해결책 (제일 쉬움)**: 그 창에 이걸 켜 두세요.

```bash
cys events --reconnect
```

회사 소식이 계속 흘러가므로 "조용한 창" 판정 자체가 안 됩니다. **그리고 이게 이 자리의 가장 좋은 용도이기도 합니다 — 회사 전체가 흐르는 창문이 되니까요.**

### ⚠️ 2. AI와 똑같은 프로그램을 오래 돌리지 마세요

같은 명령이 여러 개 돌면 시스템이 "중복 낭비"로 보고 정리하려 듭니다. 잠깐 쓰는 건 괜찮습니다(45초 이상 겹쳐야 눈에 띕니다).

### ⚠️ 3. Enter 치기 전에 한 줄 보세요

드물지만 AI가 이 창으로 메모를 보낼 수 있는데, 이 창은 **명령을 치는 자리**라 그 메모가 명령문처럼 놓입니다. 무심코 Enter를 치면 실행됩니다.
→ **내가 안 친 글자가 프롬프트에 있으면, 지우고(Ctrl+U) 치세요.**

### ⚠️ 4. 명찰을 건 상태로 창을 닫지 마세요 (7장 참고)

명찰(역할)을 건 창을 [×]로 닫으면 cys는 *"사람이 의도적으로 없앴다"*고 판단해 **묘비**를 세웁니다. 그 역할은 다시 자동으로 살아나지 않습니다.

되돌리려면:
```bash
cys tombstone <역할이름> --remove
```

## 6. 이 창을 지워도 되나요?

**네, 지워도 아무 문제 없습니다.**

창 제목 줄 오른쪽의 **[×] 버튼을 두 번** 누르면 닫힙니다(실수 방지를 위해 2회입니다). 명찰을 걸지 않은 빈 창이라면 묘비도 안 생깁니다.

다시 필요하면 상단의 **`+ New`** 버튼으로 언제든 똑같은 창을 만들 수 있습니다.

**다만 권합니다 — 이름 붙여서 당신 자리로 쓰세요.** 지우면 다음 업데이트 때 또 생깁니다.

## 7. 조금 더 — 이 자리를 AI에게 빌려주기

빈 자리에 AI를 앉힐 수도 있습니다. **세 단계가 있고, 위로 갈수록 제대로 된 직원**이 됩니다.

### 🥇 1급 — 그냥 내 자리로 쓰기 (권장)
지금까지 설명한 그대로. 지휘·결재·브레이크·확인이 다 됩니다.

### 🥈 2급 — 임시 알바 (그 창에서 `claude` 실행)

그 창에 `claude`라고 치면 AI가 뜹니다. 이때:

- ✅ **오는 것**: 자비스의 인격·기억·안전 가드 (설정에 붙어 있어서 자동으로 옵니다)
- ❌ **안 오는 것**: 직무 지침(무슨 일 하는 사람인지 모름) · 이름(아무도 못 부름) · **죽어도 감지 안 됨** · 재시작하면 사라짐 · 전용 계정 대신 개인 계정 사용

→ **30분짜리 잡무엔 좋고, 밤새 맡기는 일엔 부적합합니다.**

정식 직원과 같은 환경을 흉내내려면 이렇게 띄우세요:
```bash
CLAUDE_CONFIG_DIR=~/.cys/claude claude --dangerously-skip-permissions
```

### 🥉 3급 — 명찰 달기 (`cys claim-role`)

```bash
cys claim-role worker
```

이러면 **이름으로 불릴 수 있게 되고**, 죽은 직원이 돌아올 때 **새 창을 만들지 않고 이 자리로 옵니다.** 여전히 직무 지침·계정 격리·사망 감지는 없습니다(반쪽 직원).

> ⚠️ 명찰을 건 뒤에는 [×]로 닫지 마세요 (5장 주의사항 4번).

### 🏅 정식 직원 — 두 가지 방법

완전한 직원은 ① pane에서 `claude` 실행 후 "너는 마스터다" 선언(UserPromptSubmit 훅 체인이 자동 부트) ② `cys launch-agent --role <역할> --agent claude` — 두 방법 모두 **자리 만들기 + 지침 주입 + 명찰 + 전용 계정**을 한 번에 만들어 줍니다.

**요약**: 빈 자리는 아무리 손을 써도 3급까지입니다. 그리고 그게 좋은 일입니다 — 그래야 **언제든 명찰을 떼고 당신 자리로 되돌릴 수 있으니까요.**

## 8. 자주 묻는 질문

**Q. 이 창을 지우면 AI들이 죽나요?**
A. 아니요. 전혀 무관합니다. 이 창엔 아무도 살지 않습니다.

**Q. 업데이트할 때마다 생기는데, 안 생기게 할 수 없나요?**
A. 지금은 없습니다. 화면이 텅 비는 걸 막으려고 일부러 만드는 창이기 때문입니다. 이름을 붙여 당신 자리로 쓰시는 편이 낫습니다.

**Q. `+New`로 만든 창과 뭐가 다른가요?**
A. 다르지 않습니다. 프로그램 내부적으로 **완전히 같은 물건**입니다.

**Q. 여기서 친 명령이 AI들에게 영향을 주나요?**
A. `cys`로 시작하는 명령만 그렇습니다. 일반 명령(`ls`, `git status` 등)은 그냥 평범한 터미널입니다.

**Q. 실수로 AI를 망가뜨릴 수 있나요?**
A. 이 자리에서 위험한 것은 `cys close-surface`(창 강제 종료)와 `cys kill`(프로그램 종료) 정도입니다. 그 외 이 문서의 명령들은 전부 안전하거나 되돌릴 수 있습니다.

**Q. `cys pause`를 눌렀는데 어떻게 푸나요?**
A. `cys resume`. 컴퓨터를 껐다 켜도 멈춤이 유지되므로, 잊지 말고 풀어주세요.

## 한 장 요약

```
┌───────────────────────────────────────────────────────────┐
│  이 빈 창 = 당신(사장)의 책상입니다. 고장이 아닙니다.        │
├───────────────────────────────────────────────────────────┤
│  제일 먼저   제목 줄 우클릭 → [이름 변경] → "◆ 내 자리"      │
│  켜 두기     cys events --reconnect   (회사가 흐르는 창문)   │
├───────────────────────────────────────────────────────────┤
│  급할 때     cys pause          전부 멈춤 (풀기: resume)    │
│  살펴보기    cys status         전 직원 현황                │
│  되돌리기    cys queue clear    안 보낸 지시 취소            │
│  결재하기    cys feed list      →  cys feed reply <번호> allow │
│  되살리기    cys restore --include-master                   │
├───────────────────────────────────────────────────────────┤
│  못 하는 것  ① 인감(approval sign) ② 장부 실행(cys run)     │
│              ③ 이름으로 불리기  → 전부 정상입니다            │
├───────────────────────────────────────────────────────────┤
