# cys 0.15.0 릴리스 노트 (작성 중 — 「스스로 해결」 1차)

> 이 파일은 0.15.0 발행 노트의 자리다. 구현 트랙마다 자기 절을 덧붙이고, 발행 때 하나로 다듬는다.
> 아래 절은 앱 안쪽 수정 보관(설계 v0.5 §4-16 · 장치 M16 · 트랙 T7a)의 몫이다.

## 앱 안쪽(맥 앱 번들 · 윈도우 설치 폴더)을 고친 경우

### 첫 업데이트(0.15.0 으로 올리는 업데이트)는 보존을 보장하지 못합니다

맥의 앱 번들(0.14.56 이하) 안쪽이나 윈도우의 옛 설치 폴더 안쪽을 직접 고쳤다면, 그 수정은 0.15.0 으로 올리는
업데이트 한 번에 한해 보존을 보장하지 못합니다. 옛 버전에는 아래의 보관 장치가 없기 때문이며, 이번 판에서
정해진 예외입니다. 팩(`~/.cys/pack`)의 수정은 전부 보존됩니다.

### 0.15.0 부터: 업데이트 직전에 바뀐 파일을 복사해 둡니다(막지 않습니다)

- 앱 자신의 업데이트 처리부가 **설치를 시작하기 전에** 앱 안쪽 동봉 런타임(`runtime/`)에서 바뀐 파일(고친 것·더한
  것·지운 것)을 찾아 `~/.cys/local/bundle-edits/<옛 버전>-<UTC 시각>/` 에 바이트 그대로 복사해 둡니다. 무엇을 찾았고
  무엇을 복사했는지는 같은 폴더의 `index.json` 에 적힙니다 — 항목마다 종류(파일·링크·특수 파일), 그때 있었는지(없으면
  지운 것), 이 폴더에 보관했는지, 파일이면 검사한 해시, 링크면 그 대상이 들어갑니다(링크와 특수 파일에는 해시가 없습니다).
  - 맥: 새 버전을 내려받아 설치하는 호출 바로 앞.
  - 윈도우: 설치 파일을 내려받은 뒤, 설치 프로그램을 쓰고 실행하기 바로 앞.
- **업데이트를 막지 않습니다.** 복사에 실패해도 업데이트는 그대로 진행하고 한국어 알림을 한 번 띄웁니다. 업데이트를
  멈추게 하면 예전의 '같은 버전 재설치 → 영원한 종료 코드 4' 사고와 같은 고착이 생기기 때문입니다. 윈도우에서는 앱이
  설치 프로그램을 띄우고 곧바로 닫히므로, 그 알림은 기록해 두었다가 **다음에 앱을 열 때 한 번** 보여 줍니다.
- 업데이트가 이 확인 때문에 기다리는 시간은 **길어야 40초**이고(확인 30초 + 여유 10초), 한 번에 복사하는 크기는
  256MiB 까지입니다. 넘으면 그 자리에서 멈추고 알린 뒤 업데이트를 진행합니다(복사하지 못한 파일은 `index.json` 에
  목록으로만 남습니다).
- **디스크 여유 공간이 부족하면 복사하지 않습니다.** 보관할 디스크의 여유 공간이 2GiB + 256MiB 보다 적거나 잴 수
  없으면, 아무것도 복사하지 않고 바뀐 파일의 목록만 남긴 뒤 알립니다 — 맥에서는 이 확인이 새 버전을 내려받기 **전에**
  돌기 때문에, 보관 때문에 내려받기가 실패하는 일이 없게 하려는 것입니다.
- **같은 업데이트를 다시 시도해도 다시 복사하지 않습니다.** 같은 옛 버전에서 바뀐 파일이 그대로라면(경로·종류·해시가
  같으면) 이전에 보관한 폴더를 가리키는 목록만 새로 남깁니다.
- 무엇을 '수정'으로 세는가: 앱과 함께 배포된 런타임 목록표(`runtime-manifest.json`)와 비교해 달라진 파일입니다.
  업데이트가 남긴 잔여 파일(`*.prev<숫자>`)과 파이썬 캐시(`__pycache__`)는 수정으로 세지 않습니다.
- 보관한 수정을 새 버전에 **다시 입히는 것은 자동이 아닙니다.** 마스터에게 맡기면 워커가 확인한 뒤 다시 입힙니다.
- 보관 폴더는 앱이 지우지 않습니다.

### 덮지 않는 길 — 최선 노력이지 보장이 아닙니다

앱 안쪽 수정은 「스스로 해결」 1차가 지원하는 수리 범위 밖입니다. 다음 경우에는 앱의 업데이트 처리부가 관여하지
않으므로 보관하지 않습니다.

- 홈페이지에서 받은 설치 프로그램으로 다시 설치하는 경우
- 윈도우에서 확인 실행을 끈 경우(`CYS_UPDATE_CHECKED_LAUNCH=0`)
- 업데이트가 설치 파일이 아닌 꾸러미로 내려온 경우
- 옛 설치 프로그램을 다시 실행하는 경우

### 윈도우 설치 프로그램은 바뀌지 않았습니다

0.15.0 은 윈도우 설치 프로그램(NSIS)을 고치지 않았습니다. 설치 훅 파일(`src-tauri/nsis-hooks.nsh`)과 윈도우 번들
설정(`src-tauri/tauri.windows.conf.json`)은 0.14.56 과 바이트까지 같고, 브랜치 CI 와 앱 시험이 그것을 검사합니다.

### 아직 재지 않은 것

윈도우에서의 동작(이 보관 장치가 실제 윈도우 PC에서 걸리는 시간, 한글·긴 사용자 이름 경로, 백신이 켜진 상태 등)은
실제 윈도우 PC에서 아직 재지 않았습니다. 설계 §8-2 의 윈도우 실측 16가지 기록이 있어야 윈도우 판을 발행합니다.
맥에서도 업데이트 단추를 처음부터 끝까지 누르는 시험은 다음 버전이 실제로 발행된 뒤에야 할 수 있습니다.
