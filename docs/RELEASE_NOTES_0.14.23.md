# cys 터미널 v0.14.23 (초안)

## 부서를 만들었는데 **팀이 뜨지 않던** 문제를 뿌리째 고쳤습니다 (일곱 가지 수리)

v0.14.22가 "오래 켜 두었을 때 쌓이던 조용한 고장"을 고친 판이었다면, 이번 판은 **부서를 새로
만드는 그 순간**에 걸리던 여섯 가지 문제를 고쳤습니다. 공통점은 전부 "설명서대로 했는데
아무 일도 일어나지 않았다"는 종류입니다 — 부서장이 혼자 깨어난 채 멈춰 있고, 자기가
부서장인 줄 모르고, 오너가 부서 창에 글자를 넣으면 거부당했습니다.

> **확정과 미확정을 먼저 밝힙니다.** 아래 수리는 코드와 자동 테스트로 검증했습니다.
> 실기(실제 기계) E2E 와 Windows 실기 확인 범위는 맨 아래 **[확정과 미확정]** 절에
> 그대로 적었습니다.

---

## 1. 부서를 만들어도 **팀이 뜨지 않던** 문제 (결함 1·2)

부서 워크스페이스를 만들고 그 창에서 "너는 마스터다"라고 선언하면, 부서장은 깨어나지만
**혼자였습니다**. CSO·워커·리뷰어가 뜨지 않고 그대로 멈춥니다.

원인은 두 겹이었습니다. 부서의 팀 기동에는 **CEO가 발급한 허가증(티켓)** 이 필요한데,
① `＋부서` 버튼으로 만든 부서에는 그 허가증이 **발급되지 않았고**(자동 발급은 "본부 창에서
두 번째로 선언하면 부서가 자동 생성되는" 다른 경로에만 배선돼 있었습니다),
② 허가증이 없을 때 부서장이 **스스로 요청하지도 않았습니다**(안내문만 출력하고 대기).
그래서 오너가 추가 명령을 직접 치기 전에는 아무 일도 일어나지 않았습니다.

**고친 방식**
- **부서를 만드는 행위 자체를 발급 동의로 봅니다.** 부서 생성(`launch`·`create`·`allocate`)
  직후, CEO 승격이 끝난 시점에 허가증을 자동 발급합니다. 유효한 허가증이 이미 있으면
  다시 발급하지 않습니다(멱등 — 유효기간이 공연히 초기화되지 않습니다). 발급이 실패해도
  **부서 생성은 절대 무너지지 않습니다**(경고 한 줄 + 수동 발급 명령 안내).
- **허가증이 없으면 부서장이 스스로 CEO에게 요청합니다.** 부트 과정이 안내문만 내고 끝나는
  대신, CEO에게 발급 요청을 보내고 도착을 기다렸다가 **팀 기동까지 이어갑니다**. 요청은
  대상이 조용해질 때 배달되는 방식이라 오너가 타이핑 중인 창을 밟지 않습니다. 요청이
  실패하거나 허가증이 오지 않아도 부트는 실패하지 않고 종전처럼 단독 각성으로 남습니다.

## 2. 부서장이 **자기가 부서장인 줄 몰랐던** 문제 (결함 3)

부서의 마스터가 자신을 "부서장"으로 인식하지도, 그렇게 말하지도 않았습니다. 원인은 단순
했습니다 — **"너는 이 부서의 부서장이다"라고 말해 주는 문서가 어디에도 없었습니다.** 부서
팩은 본부와 똑같은 표준 지침과 빈 운영헌장(soul) 템플릿으로 시작했기 때문입니다.

**고친 방식**: 부서 운영헌장을 처음 만들 때 **부서 이름이 박힌 정체 문단**을 새깁니다 —
이 데몬은 어느 부서이고, 이 데몬의 마스터는 그 부서의 **부서장**이며, 본부의 마스터는
CEO이고, 각성 보고 첫 문장에 자기 정체를 밝히라는 지시까지 함께 들어갑니다.

또한 v0.14.22에서 부서 운영헌장이 **본부 운영헌장을 물려받도록** 바뀌었는데, 그대로 두면
본부에만 해당하는 문단(예: "이 데몬의 마스터는 CEO다")이 부서로 흘러가 **부서장이 자신을
CEO로 오인**하는 새 문제가 생깁니다. 그래서 **"본부 전용 · 승계 금지"로 표시된 문단은
물려줄 때 제거**하도록 했습니다.

## 3. 오너가 **부서 워커 창에 글자를 넣을 수 없던** 문제 (결함 6)

오너가 GUI에서 부서의 워커 창에 입력하면 이렇게 거부당했습니다 —
`입력 전송 실패 … acl denied: external → worker`.

부서에는 "바깥에서 워커를 직접 조종하지 못한다"는 안전 규칙이 있습니다(부서장을 건너뛴
지시를 막아 부서의 자율성을 지키기 위한 것으로, 이 자체는 옳습니다). 문제는 그 규칙이 말하는
"바깥"에 **오너의 GUI까지 포함**돼 있었다는 점입니다. 즉 시스템이 주인을 외부인으로 취급
했습니다.

**고친 방식**: 규칙을 없애는 대신 **"오너" 신원 등급을 새로 만들었습니다.** 데몬은 자기가
기동할 때 발급한 표식을 요청에 실은 상대만 오너로 인정합니다 — 그 표식은 GUI(Tauri)만
붙이고, 명령줄 도구·워커 push·큐 배달은 어디서도 붙이지 않습니다. 오너로 인정되면 모든
노드에 입력할 수 있고, **바깥에서 워커를 직접 조종하는 것을 막는 기존 차단은 그대로**입니다.
오너 규칙이 없는 기존 설치본에서는 판정 결과가 **종전과 완전히 동일**합니다(하위호환).

## 4. 부서에서 벌어지는 일이 **본부 화면에 안 보이던** 문제 (결함 4)

승인 목록에 "다른 워크스페이스(부서)의 대기 건은 여기 나오지 않습니다"라는 안내만 있고,
정작 그 부서에서 무엇이 기다리는지는 볼 수 없었습니다. 부서장이 허가증을 기다리며 멈춰 있어도
오너 화면에는 아무 단서가 없어, 사용자 입장에서는 **"그냥 멈췄다"** 로만 보였습니다.

**고친 방식**: 부서에서 기다리는 건수와 상태를 본부 화면에서도 확인할 수 있게 하고, 단독
각성 보고문이 **원인(허가증 없음)과 지금 무엇을 하고 있는지(요청 보냄·대기 중)** 를 함께
말하도록 바꿨습니다.

## 5. 기계가 보낸 알림이 **오너의 지시로 둔갑하던** 문제 (결함 5)

작업 도구가 자동으로 보내는 알림(예: "백그라운드 명령이 끝났습니다")이 **오너가 직접 친
지시로 기록**돼, 진짜 지시를 덮어쓰는 일이 있었습니다. 기존 방어는 노드 사이의 배달 기록을
대조하는 방식이라, **배달 기록을 거치지 않는 도구 내부 알림**은 걸러내지 못했습니다.

**고친 방식**: 도구 내부 알림의 형태(감싸는 태그)를 알아보고 **지시로 등록하지 않습니다.**
오너가 그런 낱말을 본문에서 언급하는 것은 정상 지시로 통과시킵니다(과잉 차단 금지).

## 6. 새 기계에서 **자가진단이 오류로 죽던** 문제 (결함 7 — 작업 중 발견)

위 여섯을 검증하다가 하나를 더 찾았습니다. 팀 편성 점검기의 자가진단(`--self-test`)이 **검사
대상 목록을 기계에 실제로 설치된 리뷰어 도구에서 뽑고** 있었습니다. 그래서 gemini·codex를
설치하지 않은 **깨끗한 기계**(=대부분의 새 사용자)에서 자가진단을 돌리면, 검사 항목이 목록에
없어 파이썬 오류 메시지(트레이스백)를 뱉고 죽었습니다.

**고친 방식**: 자가진단이 쓰는 목록을 **환경 감지가 아니라 테스트 상수로 고정**했습니다(이
모듈이 이미 다른 함수에서 쓰던 '밀폐 주입' 관례를 그대로 적용). 실제 운영 경로는 종전과 완전히
동일합니다 — 값을 주지 않으면 예전처럼 실제 감지를 씁니다.

## [확정과 미확정]

- **확정**: 위 여섯 수리는 전부 코드로 들어갔고, 각 항목에 자동 테스트를 붙였습니다.
  부서 ACL·허가증 발급·운영헌장 승계는 **격리된 임시 환경에서 실제로 돌려** 확인했습니다
  (오너의 실제 부서·설정은 건드리지 않았습니다).
- **미확정**: Windows 실기 확인은 이 판에서도 CI 게이트에 의존합니다. GUI 표시(4번)는
  화면 확인이 필요한 항목이라 자동 테스트가 대신하지 못하는 부분이 남습니다.
- **되돌리기**: 여섯 수리 전부 기존 동작을 파괴하지 않는 방향(추가·fail-open)으로 넣었습니다.
  오너 규칙이 없는 설치본, 허가증 발급이 실패한 부서, 도구 알림이 아닌 일반 입력 — 어느
  경우에도 종전 동작이 그대로 남습니다.
