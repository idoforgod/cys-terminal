# cys 터미널 v0.14.18

## "너는 마스터다"라고 했는데 팀 대신 **부서만 늘어나던** 문제 수리

마스터를 선언했는데 팀이 뜨지 않고, `cys list` 의 role 열은 비어 있고(`role=-`), 그런데 선언할
때마다 `dept-2`, `dept-3` … 부서만 늘어난다는 보고를 받았습니다. macOS·Windows 공통이며,
Windows 에서 더 자주 나타났습니다.

**증상 한 줄**: 마스터 등록이 조용히 실패하는데, 화면에는 "살아있는 마스터가 이미 있습니다"라는
**사실과 다른 안내**가 나오고, 그 오진을 근거로 부서가 자동 생성됐습니다.

### 무슨 일이 있었나

역할 등록(`claim-role`)은 위조를 막기 위해 "누가 요청했는지"를 프로그램의 자기 신고가 아니라
**프로세스 족보**로 확인합니다. 그런데 마스터 선언을 받은 훅은 부팅 스크립트를 백그라운드로
띄우고 곧 종료하기 때문에, 그 부팅 스크립트는 부모를 잃고 족보가 끊깁니다. 그래서 데몬은
"요청자를 특정할 수 없음"으로 거부했습니다.

문제는 그 거부가 **"이미 다른 마스터가 살아 있음"과 똑같은 코드**로 나왔다는 점입니다. 부팅
스크립트는 그것을 "두 번째 마스터 선언"으로 읽고 설계대로 부서를 만들었습니다 — 정작 마스터는
아무도 없는데 말입니다.

실측으로 확인했습니다. 같은 세션·같은 순간에 같은 명령을 두 방식으로 실행했을 때:

| 실행 방식 | 결과 |
|---|---|
| 창 안에서 그대로 실행 | `registered: master → surface:1` (성공) |
| 백그라운드로 분리해 실행 | `caller (surface None)` 거부 → 화면엔 "살아있는 보유자가 있다" |

### 수리 — 세 겹

1. **데몬**: "요청자를 특정 못 함"과 "역할이 이미 남에게 있음"을 **다른 코드로 분리**했습니다.
   이제 전자는 `rc 6`(발신 신원 미확정)이고, 부서 자동 생성으로 이어지지 않습니다. 안내 문구도
   "세션 배선을 점검하라"로 정확해집니다.
2. **부팅 순서**: 역할 등록을 **프로세스 족보가 살아 있는 시점**(백그라운드로 분리되기 전)에
   끝내도록 옮겼습니다. 훅이 등록을 마치고 그 결과를 부팅 스크립트에 넘기며, 부팅 스크립트는
   같은 등록을 두 번 치지 않습니다. 백그라운드 분리 자체(하네스 종료에 부팅이 함께 죽는 것을
   막는 장치)는 그대로입니다.
3. **부서 생성 가드**: 부서를 자동 생성하기 **전에** "정말 살아있는 마스터가 있는가"를
   `cys status` 로 직접 재봅니다. 없으면 부서를 만들지 않고, 측정 자체가 실패해도 만들지
   않습니다. 데몬만 구버전인 조합(앱 업데이트 후 재시작 전)에서도 부서 증식이 막힙니다.

### 이미 잘못 생긴 부서 정리

이번 수리는 앞으로의 재발을 막습니다. 이미 만들어진 부서는 그대로 있으니, 앱에서 부서 탭을
우클릭해 **완전 삭제**하거나 `cys-dept down <이름>` 으로 정리하세요.

### 회귀 고정

- 데몬 단위 테스트: 신원 미해석 거부가 **정당거부 코드로 다시 뭉치면 적색**(`claim_role_unresolved_caller_is_not_claim_denied`).
- 부팅 체인 테스트: 전제(살아있는 마스터) 미확인 시 부서 미생성·`exit 10` / 선행 등록 판정 소비 시 중복 등록 0.
- 건강성 검체 `H-IDENT-1`: 세 겹이 모두 실려 있고 **순서까지** 맞는지(등록이 분리보다 먼저,
  실측이 부서 생성보다 먼저) 확인하며, Windows 실기 레인에서도 함께 돕니다.

## Windows Defender / SmartScreen 안내 (유지)

Windows 설치 파일은 코드 서명 평판이 쌓이기 전까지 SmartScreen 경고("알 수 없는
게시자")가 뜰 수 있습니다. **"추가 정보" → "실행"** 으로 진행하시고, 다운로드한 파일은
홈페이지의 `SHA256SUMS.txt` 와 대조해 무결성을 확인할 수 있습니다. Defender 오탐은 WDSI
신고를 거쳐 릴리스마다 최소화합니다.

### Defender가 `cys.exe` 를 격리한 경우 — 복구는 **순서**가 생명입니다

드물게 Defender의 행동 휴리스틱(`Behavior:Win32/Execution.A!ml`)이 명령줄 실행 파일만
오탐 격리할 수 있습니다. 이때 앱과 데몬은 살아 있는데 CLI만 사라져 부팅 체인이 멈춥니다.
**제외를 먼저 등록하고, 그 다음 복원하세요** — 순서를 바꾸면 실시간 보호가 복원 직후
다시 격리합니다.

```powershell
# ① 제외 먼저 (관리자 PowerShell)
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\cys"
# ② 그 다음 복원
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Restore `
    -Name "Behavior:Win32/Execution.A!ml" -Path "$env:LOCALAPPDATA\cys\cys.exe"
```
