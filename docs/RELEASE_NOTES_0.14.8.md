# cys 터미널 v0.14.8

## 위임 품질 계층 Phase 1 — 도구는 실었고, 스위치는 아직 내려가 있다

워커 위임의 품질을 기계로 붙잡는 계층(검증 명세·완료 게이트·승인 통합 큐·훅 등록 도구)을 팩에
싣는다. Wave A~D 4단 + BLOCKER 수리 2단, 총 7커밋이다.

> ### ★먼저 읽을 것 — 이번 릴리스는 **기본값에서 아무것도 하지 않는다**
>
> 아래 기능은 전부 **명시 호출·명시 등록·명시 env** 로만 동작한다. 설치하는 것만으로
> 켜지는 것은 없다. 주기 호출자 0 · 훅 등록 0 · 데몬 참조 0 이다.
>
> 설치 전후로 실제로 달라지는 것은 **딱 셋뿐**이고, 셋 다 차단력이 0 이며 종료코드를 바꾸지 않는다:
>
> | 무엇이 | 어디서 | 얼마나 |
> |---|---|---|
> | 안내 문구 1줄 | 태스크 체크아웃 시 stderr | 결과·산출물·종료코드 전부 종전과 동일 |
> | 진단 항목 4행 | 부팅 진단표 | 기존 70개 항목 판정 변화 0건 · 종료코드 불변 |
> | 로그 1줄 | 세션 시작 시 `_round/.state_log` | 세션당 1줄 |
>
> **실제 발효(완료 게이트 무장 · 검증 강제 모드 · 훅 등록 · Slack 발신)는 전부 별도 승인 뒤입니다.**
> 근거는 A/B 실측 문서 `PACK-ACTIVATION-SAFETY.md` 이며, "종전 동작을 바꾸면 기본 OFF로 내린다"는
> 규칙을 적용해 이번 수리에서 **2건을 실제로 강등**했다(아래 '되돌릴 수 있게 만든 것' 참조).

### 무엇이 실렸나 (켤 때를 위한 준비물)

- **검증 명세(verify spec)와 체크아웃 게이트** — 태스크마다 "무엇으로 끝났다고 인정할지"를 미리
  적어 두고, 그게 없으면 체크아웃 때 알려 준다. 지금은 **알림(warn)** 이 기본이고, 실제로 막는
  강제 모드는 오탐 0 실측과 승인을 거친 뒤에만 켠다.
- **완료 게이트(completion-guard)** — 워커가 "다 했다"고 멈출 때 검증을 실제로 돌렸는지 확인하는
  장치. 무장하려면 훅 등록과 환경변수 **둘 다** 필요하다. 어느 하나라도 없으면 파이썬조차
  띄우지 않고 즉시 빠져나온다(미무장 상태의 프로세스 스폰 0건).
- **위임 브리프 린터** — 위임 지시문에 파일 경로·완료 기준 같은 필수 요소가 빠졌는지 짚어 주는
  검사기. 경고만 하고 절대 막지 않는다(fail-open · 300자 상한 · 위임당 1회).
- **승인 통합 큐** — 여기저기서 올라오던 승인 요청을 한 줄에 모으고, 중복은 합치고, 폭주하면
  눌러 주고, 하루치를 한 장으로 묶어 준다. 어떤 경합·중단에서도 **승인 항목이 조용히 사라지지
  않는 것**이 이 큐의 첫 번째 계약이다(소실 판정은 원장 재생 단독).
- **훅 등록 도구** — 위 장치들을 프로필에 등록할 때 쓰는 도구. **미리보기가 기본**이고,
  실제 쓰기는 `--apply` 를 명시해야 하며, 쓰기 전에 반드시 백업을 만든다. 같은 명령을 두 번
  돌려도 파일이 바이트 단위로 동일하다. **master 프로필에 완료 게이트를 다는 것은 거부**한다
  (역할 경계 — 지시를 내리는 쪽의 응답이 막히는 사고를 구조적으로 차단).
- **부팅 진단 4항목 추가** — 위 장치들이 서로 어긋나 있지 않은지, 훅이 몰래 빠지지 않았는지,
  경고 경로가 무음인지를 부팅 때 표로 보여 준다.

### 되돌릴 수 있게 만든 것 (기본 OFF로 내린 2건)

배포하면 승인 없이 켜지는 항목을 전수로 A/B 측정했고, **종전과 조금이라도 다르게 동작하는 것은
기본값을 OFF로 내렸다**.

- **체크아웃 사이드카 자동 기록** — 원안은 cys 안의 모든 체크아웃이 새 파일을 남겼다(회수 규칙
  없음 + 엉뚱한 창에 기록되는 이음매). 명시 인자를 줄 때만 기록하도록 내렸다.
- **부팅 진단 C75의 심각도** — 원안은 설치 직후 상태에서 부팅 진단을 READY → NOT READY 로
  뒤집었다. 정작 그 시점엔 강제 모드가 꺼져 있어 **막고 있는 게 아무것도 없는** 거짓 경보였다.
  강제 모드를 실제로 쫓을 때만 실패로 잡도록 내렸다.

또한 완료 게이트를 **끄면** 고위험 완료가 영구 차단되던 롤백 비대칭을 해소했다(안전밸브 신설 +
게이트 해제 시 자동 강등). 끄는 길이 없는 안전장치는 안전장치가 아니다.

### 내부 강화(운영자·기여자)

- 완료 게이트: 판정 10종(차단은 검증 실패 하나뿐 · 나머지 전 오류 경로 fail-open), 양보 사다리
  6단(재진입 마커 → 부팅 유예 → 컨텍스트 → 자원 → 검증 예산 → 명세 부재), 프로세스 그룹 통제와
  50초 데드라인, 3회 반복 시 상위 보고, 오버라이드 감지(카운터 기반 · 에피소드당 1회).
- 이식성: 셸 호출을 플랫폼별로 분기하고(POSIX/Windows), 타임아웃을 `timeout`→`gtimeout`→파이썬
  실행기 4겹으로 만들어 coreutils 부재 환경에서도 상한이 무너지지 않게 했다. **Windows는 기본
  무장 거부**(실기 회귀 하네스 확보 전까지 opt-in조차 잠금).
- 침묵 무발동 탐지기: 방어 장치가 조용히 발동하지 않는 상태 자체를 세어 경보한다(무검증 종결이
  연속 N회 → 1회 경보 + 부팅 진단 WARN). 안 울리는 알람을 알람이라 부르지 않기 위한 짝이다.
- 훅 등록 대상표를 **단일 표**(`state/hook-targets.json`)로 모으고 도구가 그것을 읽게 했다.
  표에 없는 프로필은 **기본 거부**다. 설치 직후에도 보호가 발효하도록 3단 폴백(운영 표 →
  배포 예시표 → 코드 기본값)을 뒀고, 표가 손상되면 폴백하지 않고 **쓰기 0으로 멈춘다**.
- 검증 예산(tax): 창 단위 상한을 창구별로 합산하고, 한도 초과는 **차단이 아니라 보류**다
  (소진이 전 워커 동시 정지로 번지는 되먹임을 금지).
- 회귀 자산: 도구별 자기검증 7종 + 신규 스위트 2종(`test_verify_gate` 9케이스 ·
  `test_preflight_phase1_checks` 19케이스) = **9/9 그린**이 착지 조건이었다.

### 발행 위생

공개 리포·팩 임베드 대상이므로 예시 표와 검체의 개인 식별 정보(실 사용자 홈경로·개인 프로필
이름)를 표준 더미(`/Users/x/` · `.claude-worker`)로 통일했다. 배포되는 예시 표는 **템플릿**이며,
자기 기기의 프로필 이름은 운영 표(`$PACK/state/hook-targets.json`)에 직접 적어야 한다
(표에 없는 이름은 기본 거부 = 안전한 쪽으로 실패).

## 이번 릴리스가 바꾸지 않은 것

- **본체(데몬·GUI) 코드 0줄** — 이번 변경은 전부 팩(`cysjavis-pack/`) 안에 있다.
- 기존 태스크·위임·부팅 흐름의 **결과와 종료코드** — 위 표의 3건 외에는 바이트 단위로 동일하다.

Windows `-setup.exe`.
