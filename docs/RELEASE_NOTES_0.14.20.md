# cys 터미널 v0.14.20

## Windows 에서 **60% 컨텍스트 사이클을 막던 결함 4종**을 소멸시켰습니다

cys 에는 "60% 컨텍스트 사이클"이라는 자동 절차가 있습니다 — AI 노드(master)의 대화 기억
(컨텍스트)이 한도의 60%를 넘으면, 작업 상태를 파일로 **저장**하고, 세션을 **정리(clear)** 하고,
저장본에서 **복원**해 이어 가는 순환입니다. 사람이 개입하지 않아도 세션이 늙어 죽지 않게 하는
장치입니다. macOS 에서는 돌던 이 사이클이 **Windows 에서는 네 가지 결함이 겹쳐 매번 거부되거나
아예 시동조차 걸리지 않았습니다.** 이번 릴리스는 그 네 결함을 각각의 원점에서 소멸시키고,
그 위에 **완전자동 배선(§2)** 을 새로 올립니다.

> 이 릴리스의 Windows 수리는 코드·자동 테스트로 검증되었으나, **Windows 실기(실제 기계)
> 확인은 아직 남아 있습니다** — 무엇이 확정이고 무엇이 미확정인지는 아래
> **[확정과 미확정](#확정과-미확정)** 절에 그대로 적었습니다.

## 1. Windows 사이클 결함 4종 — 각각의 원점 봉합

### ① 유령 lease — 존재한 적 없는 폴더를 검사하다 매번 거부

사이클 저장본의 위치를 정하는 코드가, 기준 경로를 못 찾으면 **아무도 만들어 주지 않는 유령
폴더**(홈 폴더 밑 `_round`)로 떨어졌습니다. 검증자(사이클이 규칙대로 저장했는지 대조하는
감시 프로그램)는 "저장하기로 한 파일이 전부 실제로 갱신되었는가"를 보는데, 유령 폴더의 파일은
영원히 없으므로 **매번 "모호함 → 거부"** 로 끝났습니다. 이제 폴백은 실존하는 출하 디렉터리
(팩의 round 정본)로 가며, 사이클 지시문도 감시 목록과 **같은 실경로를 열거**합니다
(지시가 가리키는 곳과 검사하는 곳이 다르던 모호함 소거).

### ② 검증자가 승인 기록을 영영 못 읽던 경로 — Windows 전용 정합

검증자는 승인 기록 파일(feed)을 읽어 판정하는데, 그 위치를 **소켓 주소에서 유추**했습니다.
macOS 에서는 맞는 방법이지만 Windows 의 소켓 주소(named pipe)는 폴더가 아니라서, 유추 결과가
실존하지 않는 곳을 가리켰고 **Windows 에서는 전건 "모호함 → 거부"** 였습니다. 이제 Windows 는
데몬이 실제로 쓰는 정본 위치(`%LOCALAPPDATA%\cys`)를 단일 소스에서 재사용합니다.
macOS 경로는 한 바이트도 바뀌지 않았습니다.

### ③ 중복 실행 방지 검사가 Windows 에 없는 명령을 부르던 문제

사이클 실행자는 시동 전에 "같은 실행자가 이미 돌고 있지 않은가"를 세는데(중복 시동 방지),
그 수단이 Windows 에 존재하지 않는 명령(`pgrep`)이었습니다. 이제 Windows 에서는 PowerShell 의
표준 프로세스 조회(Get-CimInstance)로 세고, **조회 자체가 실패하면 "이미 돌고 있다"로 보수
판정**합니다 — 못 세었다고 중복 시동을 허용하지 않습니다.

### ④ "살아 있나?" 확인이 그 프로세스를 죽일 수 있던 결함

프로세스 생존 확인에 쓰던 방식(`os.kill(pid, 0)`)이 Windows 파이썬에서는 **신호 0 이 무해한
확인이 아니라 실제 종료로 동작할 수 있습니다.** 생존 확인이 확인 대상을 사살하는 은닉 결함입니다.
이제 Windows 는 파괴 없는 조회 전용 API(OpenProcess 조회 권한 + 종료코드 판독)로 확인하며,
접근이 거부되면 "존재함"으로 보수 판정합니다.

### ⑤ (추가) 검증자 pane 기동이 PowerShell 에서 파스 불능이던 회귀

검증자를 pane(터미널 분할창)에 띄울 때 종전에는 **명령 문자열을 pane 에 타이핑해 넣는**
방식이었는데, Windows 기본 셸(PowerShell)이 선두 따옴표로 시작하는 그 문자열을 명령으로
해석하지 못했습니다. 이제 pane 생성 시 **명령을 직접 지정(`new-surface --cmd`)** 해 셸 방언
문제 자체를 우회합니다. 실패가 반복되면 pane 이 무한히 쌓이던 사슬도 함께 끊었습니다.

## 2. 완전자동 사이클 배선 — **shadow(관측 전용) 기본**

지금까지 사이클의 각 단계는 사람이 시동을 걸어 줘야 돌았습니다. 이번 릴리스는 데몬의 내장
스케줄에 잡 2개를 실어 **시동까지 자동**으로 만듭니다:

- **cycle-autopilot-tick** (1분마다) — 사이클 실행자를 깨워 판정을 돌립니다.
- **cycle-verifier-watchdog** (10분마다) — 검증자 pane 이 살아 있는지 확인하고, 죽어 있으면
  다시 세웁니다(살아 있으면 아무것도 하지 않는 멱등 동작 — pane 을 새로 만들지 않습니다).

**기본값은 shadow 모드입니다** — 판정과 기록만 하고 **실제 행동(저장 지시·clear)은 하지
않습니다.** 실운영 승격(live)은 상태 폴더의 `mode` 파일로만 켭니다(환경변수 문자열을 잡에
박아 두는 방식은 버전 갱신 때 소리 없이 shadow 로 되돌아가는 함정이라 금지했습니다).

자동 시동에는 **가드 5종**이 걸려 있습니다: ① kill-switch(주인님 일시정지) 선확인
② mode 게이트(shadow 에서는 행동 변화 0 을 코드로 보장) ③ 검증자 심장박동이 신선하면 무동작
④ 60분 내 3회 이상 실패 시 백오프(재시도 중단 + 보고 1회) ⑤ 살아 있는 pane 재사용 + 잠금
(감시 잡과 사전 점검이 동시에 pane 을 만드는 경합 봉합).

### 수동 2단 승인은 그대로입니다

전자동 레인의 결정론 워처(사람 없이 기계 판정으로 승인/거부하는 감시자)는 **자기가 발행한
요청만 심사**합니다. 수동 레인(사람 또는 지정 LLM 검증자가 2단계로 승인하는 handshake)의
요청은 거부하지 않고 **조용히 건너뜁니다** — 종전에는 워처가 남의 요청을 선점 거부해 수동
레인을 무력화할 수 있었습니다.

## 3. 릴리스 무결 게이트 격상 — 발행 전 검사가 더 엄격해졌습니다

이 절은 제품 동작이 아니라 **발행 절차**의 변화입니다 — 사용자에게는 "더 검사된 산출물"로만
나타납니다.

- **SEAL-2 전칭(全稱) 정적 검사**: macOS 앱에 동봉되는 파이썬 파일들의 봉인(SEAL — 소스와
  컴파일 캐시의 대응이 어긋나지 않았다는 불변식)을, 종전의 "총계 + 표본 25개"에서
  **파일별 3종 대응·기대 집합 밖 고아 전수·헤더 플래그 전량**(3,420개, 실측 0.10초) 검사로
  올렸습니다. 표본화가 놓칠 수 있던 "한쪽에서 빠지고 다른 쪽에서 늘어 총계가 상쇄되는" 결손을
  이제 잡습니다(그 함정을 재현하는 적대 픽스처 2종을 테스트로 박제).
- **Gatekeeper degraded = 판정 불가 = 폐쇄**: macOS 의 실행 허용 판정(spctl)을 실제로 돌릴
  수 없는 환경에서는, 종전처럼 "돌릴 수 있는 것만 통과"가 아니라 **게이트 실패(exit 2)** 로
  끝납니다. "측정 불능은 통과가 아니다"를 게이트 자신에게 적용한 것입니다.
- **발행 실물 DMG 실평가 훅**: 발행 절차가 홈페이지에 올릴 **실물 DMG 그 자체**를 게이트에
  넣어 평가하고, 실패하면 발행 반영(--apply)을 거부합니다(fail-closed). 탈출구는 명시적
  플래그 하나뿐이며 사용 시 크게 기록됩니다.

## 4. 설치 후 자가진단 — 알림이 유실되던 틈을 닫았습니다

설치본의 봉인이 깨져 있으면(불완전 복사·손상) 앱이 자가진단 알림을 띄우는데, **진단이 알림
구독보다 먼저 끝나면 알림이 유실되는 시간 틈**이 있었습니다. 이제 판정을 캐시에 적재해 구독
시점에 다시 끌어오므로(pull), 순서와 무관하게 알림이 도달합니다. 알림에는 **재설치 안내
한 문장**이 함께 나갑니다.

## 5. GUI 정리 — 눌러서는 안 되게 된 버튼 3종 제거

워크스페이스 바의 **▶CEO · ▶부서장** 버튼과 커맨드 센터의 **'셸에 cys 설치'** 버튼을
제거했습니다. 노드 기동의 정본 경로는 이제 **pane 마스터 선언 훅 체인과 `cys launch-agent`**
이며(버튼과 훅 체인은 같은 부트스트랩의 두 진입점이었습니다 — 남긴 쪽이 정본), 버튼을
안내하던 문서 6곳도 함께 현행화했습니다. 이 과정에서 Windows 매뉴얼의 오서술
("설치기가 PATH 를 구성한다" — 실측상 하지 않습니다)도 정정했습니다.

## 6. memory 폴더 환경변수 4키 정본 동기

memory(노드 간 공유 기억) 폴더의 위치를 알려 주는 환경변수 키가 세대를 거치며 4개가 되었는데
(구 `AITERM_PACK_DIR` 계열 → 현 `CYS_` 계열), 이를 읽는 파이썬 도구 3종이 **서로 다른 키
우선순위로 서로 다른 폴더를 볼 수 있었습니다.** 이제 4키의 정본 목록·순서를 Rust 쪽 정의와
거울로 맞춘 상수로 통일하고, 어긋나면 테스트가 기계 대조로 잡습니다. 레거시 키만 남은 오래된
환경에서도 쓰기/미러/주입이 같은 memory 를 보게 됩니다.

## 확정과 미확정

**확정(자동 검증으로 뒷받침됨)**

| # | 사실 | 근거 |
|---|---|---|
| 1 | 사이클 실행자·검증자 자동 테스트 전건 통과 | autopilot 194건·verifier 73건 0 실패 |
| 2 | 실행자·검증자의 공유 계약 블록이 바이트 단위로 동일 | 패리티 검사 + md5 대조 |
| 3 | shadow 모드에서 행동 변화 0(무동작 보장) | 격리 재현 3종(ensure-noop·shadow-noop·foreign skip) |
| 4 | SEAL-2 전칭 검사가 상쇄 결손·플래그 변조를 잡는다 | 적대 픽스처 2종이 각각 FAIL 로 떨어짐 |
| 5 | 발행 실물 게이트가 이전 판 DMG 에서 회귀 0 | v0.14.19 DMG 실평가 통과(exit 0) |

**미확정(모르는 채로 남습니다 — 숨기지 않습니다)**

1. **Windows 실기에서의 실제 동작.** ①~⑤의 Windows 분기는 주입식 테스트와 시뮬레이션으로
   검증되었고, 실기 확증은 `windows-health` CI 레인과 실기 스모크의 몫입니다. 실기에서
   CIM 조회·비파괴 생존확인·`--cmd` 기동이 설계대로 동작하는지가 남은 질문입니다.
2. **live 승격 후의 완주.** 이번 출고본의 기본값은 shadow 입니다. 실제 저장→clear→복원
   완주는 shadow 관측 기간을 거쳐 mode 파일로 승격한 뒤에만 일어납니다.
3. **CI 러너의 degraded 실발현.** Gatekeeper degraded 폐쇄는 러너가 실평가 가능한 동안에는
   도달하지 않는 방어선입니다 — 첫 실발현은 그 환경이 왔을 때 확인됩니다.

## Windows Defender / SmartScreen 안내 (유지)

Windows 설치 파일은 코드 서명 평판이 쌓이기 전까지 SmartScreen 경고("알 수 없는
게시자")가 뜰 수 있습니다. **"추가 정보" → "실행"** 으로 진행하시고, 다운로드한 파일은
홈페이지의 `SHA256SUMS.txt` 와 대조해 무결성을 확인할 수 있습니다. Defender 오탐은 WDSI
신고를 거쳐 릴리스마다 최소화합니다. (무서명 배포 모델은 이번 판에서도 변하지 않았습니다.)

### Defender가 `cys.exe` 를 격리한 경우 — 복구는 **순서**가 생명입니다

드물게 Defender의 행동 휴리스틱(`Behavior:Win32/Execution.A!ml`)이 명령줄 실행 파일만
오탐 격리할 수 있습니다. 이때 앱과 데몬은 살아 있는데 CLI만 사라져 부팅 체인이 멈춥니다.
**제외를 먼저 등록하고, 그 다음 복원하세요** — 순서를 바꾸면 실시간 보호가 복원 직후
다시 격리합니다.

```powershell
# ① 제외 먼저 (관리자 PowerShell)
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\cys"
# ② 그 다음 복원
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Restore `
    -Name "Behavior:Win32/Execution.A!ml" -Path "$env:LOCALAPPDATA\cys\cys.exe"
```
